## 1. 🛠️ Claude Code 更新

**2.1.301**（npm 發布時間：台灣 10/15 22:34，[CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)、[npm](https://www.npmjs.com/package/@anthropic-ai/claude-code)）。大部分是修正，會影響工作方式的有這幾項：

- **Grep／Glob 失敗時不再假裝「沒有找到」**：以前搜尋程式還沒回傳結果就意外失敗時，工具會回報 no matches，現在改成回傳錯誤，明確說搜尋失敗了。
  - **我可以怎麼用**：請 AI 刪除「沒被用到」的程式碼、改函式簽章，或者確認「沒有其他地方呼叫」時，在舊版上得到的「找不到」**不能當作證據**。升級之後還是建議用第二種方式再確認一次（`git grep`、跑測試），今天的動手練習就是在做這件事。
- **Workflow agent 誤以為不用做事**：workflow 裡的 agent 讀到 harness 註記「任務文字不代表使用者授權」（防 prompt injection 的說明）後，有時會跳過自己的步驟，整個 run 卻還是回報成功。這個問題已經修好。
  - **我可以怎麼用**：如果你最近用 workflow 跑多 agent 任務，結果「成功但改動比預期少」，可能就是這個問題。升級後重跑一次。
- **切換到 context 較小的 model**：對話長度超過新 model 的上限時，現在會**先用原本的 model 摘要**，再切換過去，而且不會沒問過你就花用量額度產生摘要。從 Opus 切到 Haiku 做雜事時比較不會丟失上下文。
- **`WorktreeCreate` hook 建的 worktree**：以前離開時，可能沒有詢問就刪除還有未 push commit 的 worktree，現在會先問。用 worktree 平行開發的人，這是會丟程式碼的問題。
- **Auto mode 可觀測性**：OpenTelemetry 的 `tool_decision` 事件新增 `classifier_verdict`、`permission_mode`，以及（`OTEL_LOG_TOOL_DETAILS=1` 時）`classifier_category`，可以分辨「是 auto mode classifier 擋的，還是你的 permission 規則擋的」。延續 [10/15 早報](2026-10-15.md) 2.1.300 的 OTel 改動。
- **其他**：`/rewind` 之後 skills 不再從 model 的清單裡消失；Read 不再把 `.xlsm`、`.parquet` 這類二進位檔當文字讀（處理 Excel 巨集檔時有用）；`fable`／`best` 別名在組織沒有最新 Fable 時會自動退回前一版；VS Code 擴充套件支援 LaTeX 數學式；vim mode 新增 `%` 跳到對應括號。
- **無人值守重試**：新的 `CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS` 可以設定「額度要很久之後才重置，就直接結束，不要一直等」。適合排程跑的 headless 任務。

**跟進**：[W41 週報](../weekly/2026-W41.md) 追蹤的 GitSpawn 第二個變體（`.git/config` 執行路徑），2.1.299～2.1.301 的 CHANGELOG 裡都沒有相關修正，繼續追蹤。

## 4. 💡 開發者應用：AI 說「沒有」的時候，要怎麼確認

2.1.301 的 Grep 修正提醒了一件事：**「找到了」很容易驗證，「找不到」很難**。AI 找到一個呼叫點，你點進去就能確認；AI 說「沒有任何地方呼叫」，你通常就信了。實務上，「找不到」的結論在這幾種情況特別容易出錯：

| 情況 | 為什麼文字搜尋找不到 | 你的專案例子 |
|---|---|---|
| 平台按名稱呼叫的進入點 | 沒有任何程式碼呼叫它，是平台用名稱去找 | badminton-expense 的 `doPost`、`doGet`（Apps Script web app） |
| 用字串註冊的函式 | 名稱在字串裡，不是 `name(` 的呼叫形式 | `ScriptApp.newTrigger('dailyJob')` |
| 手動從編輯器執行的函式 | 由人執行，程式碼裡完全沒有引用 | `setup()`、`installTriggers()` |
| 動態組出名稱、HTML 裡呼叫、設定檔引用 | 名稱是拼接出來的，或在 `.html`、`.json` 裡 | `google.script.run.xxx()`、`sw.js` 的 `ASSETS` 清單 |
| 搜尋工具本身失敗 | 2.1.301 之前，失敗會被當成 0 筆 | 任何專案 |

對應的做法：在 CLAUDE.md 寫一條規則，**刪除或改名之前，要列出「這個名稱可能被外部用到的方式」並且逐一確認**，最後用測試和建置結果驗收，不要只看搜尋。下面的動手練習就是實際做一次。

## 6. 📖 今日一詞：Open-weight（開放權重）vs. Open source（開源）

- **定義**：Open-weight 是指公開**訓練好的模型權重**，讓你可以下載、自架、微調。Open source AI（依 OSI 的 Open Source AI Definition）除了權重，還要公開足夠重現訓練的資訊（訓練程式碼、資料說明），而且授權不能限制使用目的。
- **運作原理**：有了權重就能做 inference 和 fine-tune，但看不到訓練資料，也沒辦法重新訓練。實際上決定你「能用來做什麼」的是**授權條款**：商用規模上限、禁止用來訓練其他模型、使用範圍限制等。所以「開放」有三個獨立的程度：權重是否公開、訓練過程是否公開、授權是否限制用途。
- **例子**：今天的 Muse Spark Open 是 open-weight，但 Muse Model License 對商用有限制，所以媒體會說它「不算真正開放」。如果你想在公司內部自架它當 coding 模型，**要先請法務看授權**，不是能下載就能用。相對地，Apache 2.0 或 MIT 授權的模型，在授權上幾乎沒有這類限制。

## 7. 🏋️ 每日動手（約 15 分鐘）：測試 AI 在 badminton-expense 上說「這個函式沒人用」可不可信

badminton-expense 是 Google Apps Script 專案，有好幾個「程式碼裡沒有人呼叫、卻絕對不能刪」的函式：`doPost`、`doGet`（web app 進入點）、`dailyJob`（`Setup.js` 用字串 `'dailyJob'` 註冊成 trigger）、`setup`、`installTriggers`（在 Apps Script 編輯器手動執行）。這是測試 AI「找不到就當沒用」習慣的好教材。

> 在你自己電腦上的 badminton-expense 做（早報不會動你的 repo）。最後可以 `git restore .` 還原。

1. 升級並確認版本：`claude update`，`claude --version` 要 ≥ 2.1.301。
2. 在 badminton-expense 開 Claude Code，**先不要給任何提示**，直接問：
   > 列出 src/ 裡所有「沒有被任何程式碼呼叫」、可以安全刪除的函式，附上你的判斷依據。
3. 檢查答案：清單裡有沒有 `doPost`、`doGet`、`dailyJob`、`setup`、`installTriggers`？有的話，AI 就掉進了表格裡的陷阱。記下它用了哪些搜尋。
4. 在 CLAUDE.md 加一段（請 Claude 幫你加，但內容由你決定）：
   ```markdown
   ## 刪除或改名函式之前
   - 這是 Apps Script 專案：doGet/doPost 是平台進入點；trigger 用字串註冊（見 Setup.js）；setup、installTriggers 由人在編輯器手動執行。這些函式不能因為「沒有呼叫點」就刪除。
   - 判斷「沒人用」要列出檢查過的引用方式：直接呼叫、字串名稱、HTML 裡的 google.script.run、手動執行。
   - 搜尋結果是 0 筆時，再用 `git grep -n "<名稱>"` 確認一次，最後跑 `npm test` 和 `npm run build`。
   ```
5. `/clear` 之後再問一次步驟 2 的問題。這次清單應該排除這五個函式，而且會說明每個候選函式檢查過哪些引用方式。
6. 加分：問「如果把 `dailyJob` 改名成 `runDailyJob`，還要改哪些地方？」，正確答案要包含 `Setup.js` 的字串，**以及已經裝在 Apps Script 上的 trigger 要重新安裝**（這一點程式碼裡完全看不出來）。

## 8. ⚠️ 風險與辨識：AI 回報「沒問題」，但其實是工具失敗

2.1.301 一次修了兩個同類型的問題（[CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)）：Grep／Glob 失敗被當成「沒有找到」，以及 workflow agent 跳過步驟卻回報成功。兩者都是**靜默失敗（silent failure）**：沒有錯誤訊息，結果看起來很正常。

放到資安情境裡，這更危險。請 AI「確認 repo 裡沒有硬寫的 API key」或「確認沒有地方用到這個有漏洞的套件」時，「沒有找到」會被當成「安全」。

**辨識重點**：

- AI 的結論是「沒有」、「不存在」、「都已處理」時，要求它**附上實際執行的指令和輸出**，例如 `git grep -n "sk-ant" | wc -l` 的結果，而不是只給一句結論。
- 用兩種不同的工具交叉確認：Grep 工具加 `git grep`，或者搜尋加測試。
- price-tracker 是 public repo，可以免費開 GitHub 的 **AI Scan for pull requests**（10/15 正式版，[GitHub changelog](https://github.blog/changelog/2026-10-15-ai-scan-for-pull-requests-generally-available)）：它補 CodeQL 不支援的語言（Shell、Dockerfile、Terraform、JSP、Blazor for C#），結果只是建議、不會擋 merge，不需要 Copilot 授權。但它也是 AI，同樣**只能當第二意見**，不能當「已經安全」的證明。
