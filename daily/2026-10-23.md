## 1. 🛠️ Claude Code 更新

**2.1.308**（台灣 10/22 12:19，只寫「Bug fixes and reliability improvements」）與 **2.1.309**（台灣 10/23 04:34）（[CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)、[npm](https://www.npmjs.com/package/@anthropic-ai/claude-code)）。2.1.309 很長，大部分是 sandbox 和權限檢查的修正，挑會影響你的：

**行為改變（要知道）**

- **`sed -i` 改成一般的 Bash 權限提示、照原樣執行**，不再模擬成 file-edit 預覽；跟其他 Bash 修改一樣，**`/rewind` 不會還原它**。
  - **我可以怎麼用**：如果你習慣「讓它改，不對再 `/rewind`」，現在要分清楚：用 Edit／Write 改的檔案 `/rewind` 救得回來，用 `sed -i`、`node -e`、redirect 改的救不回來。重要的重構前先 `git commit` 或開 worktree，`git` 才是真正的保險。
- **Desktop app 和 VS Code 在 bypass permissions 模式下遇到危險的 `rm`／`rmdir`，直接拒絕並給改寫提示**，不再停下來問你，所以無人看管的 session 不會卡住。
- **`claude ultrareview` 需要 workspace trust**：terminal 會詢問，非互動直接拒絕。腳本要加 `--trust-workspace`（不帶值，PR 編號或 base branch 要放在它前面），或設 `CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1`。有在 CI 跑 ultrareview 的要改腳本。
- **`/claude-api` skill 建 Managed Agents 的 subagent 團隊時改用 `multiagent_20261001`**，dynamic workflows 預設開啟，取代 `coordinator`。延續 [10/22 早報](2026-10-22.md) 的 API 新版本，這個 skill 這兩天變動很快。

**安全修正（建議今天就升級）**

- **Linux／macOS：sandbox 裡的 Bash 指令，每次執行前會先在 sandbox 外跑 shell 的啟動檔**（`.bashrc`、`.zshenv` 這類）：已修正。
- **`Edit(path)` deny 規則擋不住「同時含 subshell 的指令」裡的 Bash redirect**：已修正。這正是 [10/22 今日動手](2026-10-22.md) 在測的「用 Bash 繞過 deny」；舊版上，`(cd x && echo ... > test/a.js)` 這類寫法可能過得去。
- **sandbox 指令和自動接受的編輯可以改 `--mcp-config` 指定的 MCP 設定檔**、**macOS `denyWrite` glob 在經過 symlink 的路徑上失效**、**config 目錄經過 symlink 時 profile store 寫入保護失效**、**Linux 背景指令活得比 session 久時 sandbox 寫入限制被解除**：都已修正。
- **Bash 權限檢查信任了「redirect 可能開檔失敗的指令」設定的變數**、**`cd` 被包起來或加前綴後再跑 git 的複合指令不會提示**、**worktree 隔離的 session 接受某些 locale 前綴或 zsh 算術指令**：已修正。
- **Windows：PowerShell hook 用 exit code 2 擋不下來**，以及沒裝 Git for Windows 時 `"shell": "powershell"` 的 `PreToolUse`／`PermissionRequest` hook 會 **fail-open**：已修正（fail-open 見 [W41 週報](../weekly/2026-W41.md)）。
  - **我可以怎麼用**：如果你在 Windows 上有寫 PowerShell hook 當守門員，這版之前它可能根本沒擋過任何東西。升級後故意觸發一次，確認真的會擋。

**其他值得一提**

- **超大的巢狀 CLAUDE.md 會讓 session 反覆 compaction**：已修正，超過大小上限的巢狀 CLAUDE.md 現在只載入開頭。代表**巢狀 CLAUDE.md 寫太長，後半段會被截掉**，重要規則放前面。
- **`--add-dir` 資料夾裡的 skill 跟現有 skill 撞名時無法使用**：現在會以 `<folder>:<name>` 出現。
- **split-pane 的 agent teammates 沒有繼承 leader 命令列上的 tool deny 和 `--tools`**：已修正。
- **`/rewind` 列表對透過 subagent、`/code-review --fix` 或 shell 指令改過的回合顯示「No code changes」**：已修正。
- **Code Review**：`@claude review stop` 之後，排在進行中 review 後面的 push 仍會啟動 review 的問題已修正。

**跟進**：[W41 週報](../weekly/2026-W41.md) 追蹤的 GitSpawn 第二個變體（`.git/config` 執行路徑），2.1.308／2.1.309 的 CHANGELOG 仍然沒有明確對應的修正；這版有「worktree 和 branch checkout 會忽略 git replace refs」，但看不出跟 GitSpawn 有關。

- **捐了什麼**：標準本身、名稱與 logo、GitHub organization、`agentskills.io` 網域。
- **誰維護**：Anthropic、Google、OpenAI 等公司的工程師以個人身分維護；Lead Maintainers 是 David Soria Parra 和 Mahesh Murag。
- **規模**：2025 年 12 月公開成標準以來，**70 多個 agent 平台**支援（ChatGPT、Cursor、GitHub Copilot、VS Code 等），**約 100 萬個 skill 發布、近 2.8 億次安裝**；社群也替 Codex、Cursor、OpenCode 寫了 loader。
- **接下來**：Anthropic 提議的 roadmap 包括**版本化 release、正式提案流程，以及給 skill 作者和安裝者的安全指引**。文章沒有說 Claude Code 的行為會因此改變。

**對你的意義**：

1. **skill 是目前最可攜的「AI 協作資產」**。CLAUDE.md 是 Claude Code 專屬，但 `SKILL.md`（frontmatter 的 `name`、`description` 加上內文和附屬腳本）在 Copilot、Cursor、ChatGPT 都讀得懂。你在專案裡把「怎麼部署」「怎麼發版」寫成 skill，以後換工具也帶得走。
2. **照標準寫，不要依賴 Claude Code 的擴充欄位**。想要可攜，就守住標準的核心：`name` 只用小寫英數和連字號、跟資料夾同名，`description` 寫清楚「做什麼、什麼時候用」。Claude Code 專屬的欄位（例如限制可用工具）其他平台不一定認得。
3. **安全指引即將出現，代表 skill 的供應鏈問題被正式承認了**。skill 可以帶腳本，裝別人的 skill 等於執行別人的程式碼（見 [10/19 早報](2026-10-19.md) 起討論的 `.claude/` 供應鏈攻擊面）。在官方指引出來前，裝 skill 前先讀完它的 `SKILL.md` 和 `scripts/`。

今日動手就是替 loan-tracker 寫一個照標準格式、可以帶著走的 skill。

## 6. 📖 今日一詞：Progressive disclosure（漸進式揭露）

- **定義**：先只給 agent 最少的資訊讓它知道「有這個東西」，等它判斷需要時才載入完整內容。Agent Skills 的核心設計就是這個。
- **運作原理**：Agent Skills 分三層載入：
  1. **Metadata**（`name` + `description`，每個 skill 約幾十到一百個 token）：session 開始時全部放進 context，讓模型知道有哪些 skill 可用。
  2. **`SKILL.md` 內文**：模型判斷這個任務用得到，才讀進來。
  3. **附屬檔案**（`references/`、`scripts/`、範本）：內文裡指到、真的需要時才讀或執行。腳本可以直接執行，**程式碼本身不必進 context**，只有輸出會進來。
  所以裝 50 個 skill，平常只多花 50 段 description 的 token；對比把所有規則塞進 CLAUDE.md，每一回合都要付全部的錢（見 [10/15 今日一詞 prompt cache TTL](2026-10-15.md)）。
- **例子**：今天 2.1.309 的修正「超大的巢狀 CLAUDE.md 只載入開頭」就是反例：CLAUDE.md 沒有漸進式揭露，寫太長只會被截斷。**判斷原則：每次都要遵守的規則放 CLAUDE.md（短）；只在特定任務才需要的流程（部署、發版、資料遷移）做成 skill。**也因此 `description` 是整個 skill 最重要的一行：模型只靠它決定要不要打開，寫得模糊就永遠不會被用到。

## 7. 🏋️ 每日動手（約 15 分鐘）：替 loan-tracker 寫一個可攜的「重新部署」skill

loan-tracker 的 README 有一段很容易做錯的流程：改完程式要用「管理部署作業 → 新版本」，**按成「新增部署作業」會產生新網址**，LINE 的 Webhook 就斷了；舊版試算表升級後還要重跑 `setup`、勾「還款人」。這種「只在特定任務需要、做錯代價高」的流程，正適合做成 skill。

1. 進 loan-tracker，開一個分支：`git switch -c try/deploy-skill`（練習用，不一定要合併）。
2. 開 Claude Code，貼這段 prompt：
   > 讀 README.md 的「修改程式後重新部署」與第三、四節，把重新部署的流程做成一個符合 Agent Skills 開放標準（agentskills.io）的 skill，放在 `.claude/skills/gas-redeploy/SKILL.md`。規則：frontmatter 只用 `name` 和 `description` 兩個標準欄位，`name` 必須是 `gas-redeploy`；`description` 要寫清楚「什麼時候用」，包含「改完 gas/ 的程式、要更新 Apps Script、Webhook 網址不能變」這些觸發情境；內文用檢查清單，最前面放「絕對不要按『新增部署作業』」；不要複製 README 全文，用相對路徑指回 README 對應段落。
3. 檢查它的產出：
   - `name` 是否全小寫、只有連字號、跟資料夾同名？`description` 有沒有超過 1024 字元？
   - 有沒有偷加 Claude Code 專屬欄位？（有的話問它：「這個欄位在 Copilot 或 Cursor 讀得懂嗎？」）
   - 內文是否短到一頁內，細節指回 README，而不是整段複製（progressive disclosure 的第三層）。
4. **測觸發**：`/clear` 後**不要提 skill 名稱**，說「我改好 Ledger.gs 了，接下來要怎麼更新到線上？」。看它有沒有自己載入 `gas-redeploy`。沒有的話，是 `description` 寫得不夠像使用者會說的話，改 description 再試，這就是今天最重要的練習。
5. **測可攜性（有裝的話）**：用 Copilot CLI 或 Cursor 開同一個 repo 問一樣的問題，看它是否也認得這個 skill。（Copilot CLI 讀取 skill 的路徑可能不同，若讀不到，記下來就好，不用硬改。）
6. 收尾：滿意就留著分支自己決定要不要合併；不要的話 `git switch - && git branch -D try/deploy-skill`。

## 8. ⚠️ 風險與辨識：sandbox 的漏洞在邊角，不在主流程

今天 Claude Code 2.1.309 的 CHANGELOG 等於一份「sandbox 可以怎麼被繞過」的清單（[CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)）：

- **shell 啟動檔在 sandbox 外執行**：如果一個惡意 repo 或被 prompt injection 的 agent 能先把東西寫進 `.bashrc`／`.zshenv`，之後每一個「sandbox 裡的」指令都會先在 sandbox 外跑那段程式。這跟 [CVE-2026-55607](https://mend.io/vulnerability-database/CVE-2026-55607/)（worktree 搭配 symlink 覆寫 `.zshenv`，6 月修正於 2.1.163）是同一個攻擊目標。
- **symlink**：macOS `denyWrite` 和 profile store 的保護，遇到經過 symlink 的路徑就失效。
- **你沒想到的入口**：`--mcp-config` 指定的設定檔、subshell 裡的 redirect、`cd` 被包起來的 git 指令、比 session 活得久的背景程序。

**辨識與防範**：

- **今天就升級到 2.1.309**（`claude --version` 確認；用 npm 全域安裝的跑 `npm i -g @anthropic-ai/claude-code@latest`）。
- **看自己的 `~/.bashrc`、`~/.zshenv`、`~/.profile` 有沒有你不認得的內容**，特別是最近讓 agent 在 sandbox 或 auto mode 下跑過陌生 repo 的話。`ls -la ~ | grep -E '^l'` 也順便看家目錄有沒有奇怪的 symlink。
- **不要把 sandbox 當唯一防線**。這版修了十幾個繞過，代表還會有下一批。搭配 permission deny、`git diff` 驗收（[10/22 早報](2026-10-22.md)），陌生 repo 在 container 或雲端 session 裡跑。
- 安裝別人的 skill 也是同一件事：skill 的 `scripts/` 會被執行，在 AAIF 的安全指引出來前，先讀再裝。
