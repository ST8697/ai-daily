  - **我可以怎麼用**：在 `.claude/agents/*.md` 的自訂 subagent 裡寫 `model: haiku`，讓搜尋、整理、檢查清單這類工作用 Haiku 跑，主對話留給 Opus／Sonnet。成本大概降一個數量級。
- 修正：compaction 之後 Claude 有時把壓縮前做完的事當成沒做，回頭撤銷或重做。長對話「忽然倒退」的情況應該會變少。
- 修正：用 `cat`／`head`／`sed -n`／`grep` 看單一檔案時，path-scoped rules 和子目錄的 CLAUDE.md 不會載入。現在用 Bash 讀檔也會載入。

**v2.1.294：prompt／agent hook 判斷修正（重要）**
- 修正：用指令語氣寫的 `prompt`、`agent` hook（例如「Block commands that…」）會**放行原本該擋的東西**。
  - **我可以怎麼用**：如果你寫過「用 LLM 判斷要不要擋」的 hook，更新後拿一個應該被擋的指令實際測一次，不要假設它一直都有效。
- 改進：Stop／SubagentStop 上的 prompt hook（例如「build 壞了就繼續做」）比較不會讓 Claude 太早停。

**v2.1.295：hook fail-closed、終端狀態**
- 新增 command／HTTP hook 的 `onFailure: "block"`：hook 啟動失敗、逾時或回傳非預期的 exit code 時，**擋下動作**，不再默默放行。
  - **我可以怎麼用**：拿來保護「不准做」的規則，例如禁止 `git push --force`、禁止改 `.env`。設成 block 之後，就算 hook 腳本壞了也是擋下，不會變成沒有防護。
- 新增 Program Status Protocol（OSC 7501）：支援的終端可以在分頁上顯示 Claude 正在工作、等你回覆或已完成。
- 新增 `CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS`：限制無人值守重試模式遇到 429／529 時最多等多久，適合排程任務和 CI。
- 變更：subagent 的 `skills` 欄位最多預載 32 個 skill。透過 tool search 載入的 MCP 工具描述，截斷上限從 2,048 字元提高到 16,384 字元。
- 修正：`claude -p` 在背景工作又開新 turn 時遺失前面的回覆；遠端 MCP 斷線超過 15 秒後在 headless／SDK 裡一直連不回來；Bash 跑完 `cat` 但沒有輸出內容時，檔案卻被當成已讀過。

**價格**：10/7 起 Sonnet 5.5 的 prompt cache read 價格減半，從 $0.20 降到 $0.10/Mtok（[Haiku 5.5 公告頁的價格表](https://www.anthropic.com/claude-haiku-5-5)）。長 session 和大量重用 CLAUDE.md 的用量會直接變便宜。

## 4. 💡 開發者應用

- **「主模型 + 便宜 subagent」分工正式成為主流**：Haiku 5.5 公告提到 Cognition 的 Devin CLI 用 Opus 5.5 當 lead、Haiku 5.5 當 subagent；Cursor Projects 的 coordinator 也只規劃、不寫 code。實務上可以這樣分：**需要判斷的工作（規劃、架構、審查）交給大模型，讀很多檔、跑測試、整理 log 這類吃 token 但不需要判斷的工作交給小模型**。在 Claude Code 裡，就是讓 Explore 類的自訂 agent 設 `model: haiku`。
- **Hook 要當程式碼來測**：2.1.294 修掉的 bug 說明了一件事：用自然語言寫的 prompt hook，你以為它在擋，實際上可能沒有。具有防護作用的規則優先寫成確定性的 command hook，再加上 `onFailure: "block"`。只有需要判斷語意的規則才用 prompt hook，而且要準備正反兩種測試案例。
- **Prompt caching 重新試算**：Sonnet 5.5 cache read 降到 $0.10/Mtok，Haiku 5.5 只要 $0.01。如果你有自己的 API 腳本（例如 stock-screener 之後想接 LLM 摘要），把固定的 system prompt 和資料說明放在前面並打上 `cache_control`，重複呼叫的成本幾乎可以忽略。

## 6. 📖 今日一詞：Fail-closed（vs. Fail-open）

- **定義**：防護機制**本身故障**時要怎麼處理。fail-open 是「壞了就放行」，fail-closed 是「壞了就擋下」。
- **原理**：檢查流程有三種結果：通過、拒絕、**檢查失敗**（逾時、crash、設定錯誤）。fail-open 把第三種當成通過，可用性高但有安全漏洞；fail-closed 把第三種當成拒絕，比較安全，但檢查程式一壞就會卡住工作。
- **例子**：Claude Code 2.1.295 之前，hook 腳本壞掉（例如 `jq` 沒裝、路徑寫錯）時，工具呼叫會照常執行，等於 fail-open。設了 `onFailure: "block"` 之後就是 fail-closed，hook 本身出錯時那個動作也會被擋下。原則是：**安全類規則用 fail-closed，格式化、通知這類便利性 hook 維持 fail-open**。

## 7. 🏋️ 每日動手（約 10 分鐘）：替 price-tracker 加一個「sw.js 快取清單守門員」

price-tracker 的 CLAUDE.md 有一條容易漏掉的規則：**新增、刪除或改名檔案時，要更新 `sw.js` 的 `ASSETS` 並把 `CACHE` 版本號加一**。目前是 `bijiaben-v1`，`ASSETS` 列了 `js/app.js`、`js/db.js`、`js/calc.js`、`css/style.css` 和 icons。我們把它從「請 AI 記得」改成「機器檢查」。

> 在你自己的電腦上的 price-tracker 做（早報不會動你的 repo）。

1. 開 Claude Code，輸入：
   ```
   寫一個 scripts/check-sw-assets.mjs：列出 css/、js/、icons/ 底下所有檔案，
   跟 sw.js 的 ASSETS 陣列比對。有漏掉或多出來的檔案時，把差異印到 stderr 並 exit 2；全部一致就 exit 0。
   只用 Node 內建模組。
   ```
2. 請它在 `.claude/settings.json` 加一個 **Stop hook** 執行 `node scripts/check-sw-assets.mjs`。exit 2 時 Claude 會收到 stderr，然後自己繼續補。
3. 驗證：請 Claude「新增 `js/format.js`，把 app.js 裡的金額格式化抽出去」。觀察它停下來前，是否被 hook 擋住並自動更新 `ASSETS`、把版本號改成 `bijiaben-v2`。
4. 加分：如果你的 Claude Code 版本是 2.1.295 以上，在 hook 設定加上 `"onFailure": "block"`，再把腳本檔名故意改錯，確認它會擋下，而不是默默放行。最後想一想：這個 hook 該不該 fail-closed？（提示：它不是安全規則，但漏掉的代價是使用者拿到舊版快取。）

## 9. ⚠️ 風險與辨識：「打開 repo 就中招」的 repository poisoning

Adversa 的 10 月整理（[原文](https://adversa.ai/blog/top-ai-coding-agent-security-resources-october-2026/)）提到，9 月的攻擊趨勢是「**repo 本身就是 exploit**」：在 git 設定裡埋陷阱，讓 Claude Code、Codex、Cursor 等 agent 在跳出核准提示前就執行攻擊者的程式；也有 repo 內的 subagent 設定不需要注入任何 prompt，就能讓 agent 執行 C2 payload（細節與修補狀態待確認）。

**辨識與防範**：
- clone 陌生 repo 後，先別在裡面開 agent。先看 `.claude/`、`.cursor/`、`.vscode/`、`.git/config`（`core.fsmonitor`、`core.hooksPath`、`filter.*` 都能執行程式）和 `package.json` 的 `postinstall`。
- 陌生的 repo 用雲端 session 或容器開，不要在有 SSH key、雲端憑證的主機上直接跑。
- 把 Claude Code 更新到最新版，相關的防護修補多半是靜默加在 changelog 的 Fixed 項目裡。
