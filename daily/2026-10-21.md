## 1. 🛠️ Claude Code 更新

**2.1.305**（npm 發布時間：台灣 10/21 03:29，[CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)、[npm](https://www.npmjs.com/package/@anthropic-ai/claude-code)）。大多是修正，會影響工作方式的有這幾項：

- **修正 2.1.304 的 regression：tool search 被拒絕時每個請求都失敗**：影響 Vertex、Bedrock，以及 gateway 擋掉 ToolSearch、或 `--tools` 沒列 ToolSearch 的環境。現在會自動改成不用 tool search 再試一次。
  - **我可以怎麼用**：如果你昨天升到 2.1.304 後，公司 gateway 或 `claude -p --tools ...` 的腳本突然全部失敗，原因就是這個，升到 2.1.305 即可。這也提醒一件事：**自動化腳本最好固定版本**，升級前先在一個腳本上試跑。
- **`sandbox.allowNestedUserNamespaces`（Linux）**：讓 sandbox 裡的指令可以建立 user namespace，Chromium、rootless podman 才跑得起來。CHANGELOG 直接寫明：**這也讓它們可以繞過 sandbox 的檔案保護**。
  - **我可以怎麼用**：只有在 sandbox 裡跑 Playwright／Chromium 測試卡住時才考慮，而且只放在那個專案的 `.claude/settings.local.json`，不要放進使用者層級的設定。延續 [10/14 早報](2026-10-14.md) 的教訓：commit 進 repo 的 `.claude/settings.json` 也可能被人改成開啟這個選項，review 時看到它要特別注意。
- **`/usage` 的警告變成「一行修法」，按 `f` 直接套用**：每個警告會寫出來源（哪個設定檔、哪個 MCP server），同樣的修法也會出現在 VS Code 和 `/doctor`。
  - **我可以怎麼用**：延續 [10/15 早報](2026-10-15.md) 用 `/usage` 管 context 的練習。按 `f` 之前先看清楚它要改哪個檔案；改完用 `git diff` 確認，尤其是專案的 `.claude/` 底下。
- **MCP consent 對話框不容易被誤按 Accept**：以前你在打字時按的 Enter，可能剛好被跳出來的「是否信任這個 MCP server」對話框當成同意。這是一個實際的安全改善。
- **`allowedMcpServers` 行為變更（企業管理設定）**：`managed-mcp.json` 裡只在 `env` 用到 `${VAR}` 的 stdio server，以前會被 allowlist 過濾掉，**升級後會開始載入**。要繼續關掉，得改用 `deniedMcpServers`。個人使用者通常不受影響。
- **Worktree 修正**：bare repo 新建的 worktree 有時會從本機 HEAD 開始而不是預設分支；沒有改動的 subagent worktree 有時不會被清掉。延續 [10/20 早報](2026-10-20.md) 的 `--worktree` 修正。
- **Subagent 換成 fallback 模型後，Claude 會說錯是哪個模型做的**：已修正。如果你靠 Claude 的回報判斷「這段是 Haiku 還是 Opus 做的」，以前可能不準。
- **磁碟滿時 Bash 會明確說「磁碟已滿，指令沒有執行」**，不再只丟一個 `ENOSPC` 路徑。
- **Code Review（GitHub）**：同一個 PR 在審查中途又有新 push 時，有時沒有審到最新 commit；重新審查時，如果之前的 blocking finding 還沒解決，不會再以「LGTM」開頭。

**跟進**：[W41 週報](../weekly/2026-W41.md) 追蹤的 GitSpawn 第二個變體（`.git/config` 執行路徑），2.1.305 的 CHANGELOG 裡仍然沒有相關修正，繼續追蹤。

## 4. 💡 開發者應用：把 CLAUDE.md 裡的「記得要…」變成可以執行的檢查

今天的駭客新聞說明了一件事：**agent 會照指令一直做下去，不會自己停下來想「這樣對嗎」**。不只攻擊者的 agent 這樣，你的 agent 也一樣：CLAUDE.md 寫了規則，它大多數時候會遵守，但沒有任何東西會在它忘記時擋住它。

最容易被忘記的是「做 A 的時候，順便要做 B」這種規則。以 price-tracker 為例，CLAUDE.md 寫著：

> 新增、刪除或改名檔案時，要更新 `ASSETS` 清單並把 `CACHE` 版本號加一

這條規則如果漏掉，不會有任何錯誤訊息：本機測試正常，push 上 GitHub Pages 也正常，要等到使用者**離線開啟時才發現新檔案沒被快取**。這正是適合寫成檢查的規則：

| 規則類型 | 例子 | 建議做法 |
|---|---|---|
| 風格、偏好 | 介面文字用繁體中文 | 留在 CLAUDE.md |
| 有明確對錯、可以用程式判斷 | `ASSETS` 要包含所有前端檔案 | 寫成檢查腳本，加進 `npm test` 或 hook |
| 違反後果嚴重 | 不能把 token 寫進程式碼 | 檢查腳本＋permission deny 規則 |

做法很簡單：請 Claude 把規則寫成一支小腳本，失敗時用非 0 的 exit code 結束，並印出「該怎麼修」。之後 CLAUDE.md 那條規則改成「改完跑 `node scripts/check-sw.mjs`」。檢查腳本會擋住，CLAUDE.md 只是提醒。見今日動手。

## 6. 📖 今日一詞：Diffusion language model（dLLM，擴散語言模型）

- **定義**：用 diffusion（擴散）方式產生文字的語言模型。一般 LLM 是 autoregressive（自迴歸）：一次產生一個 token，每個 token 都要等前一個產生完。dLLM 則是先產生一整段「有雜訊」的草稿，再反覆修正，每一輪都同時改很多個 token。
- **運作原理**：訓練時，把正確答案的 token 隨機遮掉（mask）或加雜訊，教模型還原。推論時，從全部被遮住的序列開始，每一步預測所有位置，把信心高的先定下來，剩下的下一步再改。步數遠少於 token 數，而且每一步都能把 GPU 用滿，所以吞吐量高。代價是：模型比較難處理「後面的內容強烈依賴前面剛產生的結果」的長推理，品質和穩定性也還在追趕 autoregressive 模型。
- **例子**：Mercury 3 每秒 1,068 token，大概是一般前沿模型的 10 倍以上。圖片生成（Stable Diffusion、Midjourney）用的是同一個想法，只是對象從像素換成 token。Coding 上最直接的應用是低延遲的程式碼補全和「下一步編輯」預測，這類任務對速度很敏感，又不需要長推理。

## 7. 🏋️ 每日動手（約 15 分鐘）：把 price-tracker 的「記得更新 `ASSETS`」變成檢查腳本

目標：練習把 CLAUDE.md 裡的規則變成 Claude 不能忽略的檢查。

1. 進 price-tracker，確認目前狀態：`git status`、`cat sw.js`。現在 `ASSETS` 有 11 個項目，`CACHE` 是 `bijiaben-v1`。
2. 開 Claude Code，貼這段 prompt：
   > 讀 CLAUDE.md 裡關於 sw.js 的規則。寫一支 `scripts/check-sw.mjs`（只用 Node 內建模組，不要裝套件）：
   > 1. 列出 `index.html`、`manifest.webmanifest`、`css/`、`js/`、`icons/` 這些前端檔案；
   > 2. 解析 `sw.js` 的 `ASSETS`，找出「有檔案但沒在清單」和「在清單但檔案不存在」兩種情況；
   > 3. 有問題就印出要怎麼修（包含「記得把 CACHE 版本號加一」），exit code 設為 1；沒問題印 OK。
   > 先不要改 CLAUDE.md。
3. 執行 `node scripts/check-sw.mjs`，應該印 OK。
4. **故意弄壞它來驗證**：`touch js/util.js`，再跑一次，應該失敗並指出 `./js/util.js` 不在 `ASSETS`。然後 `rm js/util.js`。再試一次反向：暫時把 `ASSETS` 裡的 `./js/calc.js` 改成 `./js/calcs.js`，應該報「檔案不存在」，改回來。**沒有親手看到它失敗的檢查，不能算數。**
5. 看 Claude 寫的程式碼有沒有這兩個常見問題：
   - 用 regex 解析 `ASSETS` 時，`'./'`（根目錄）有沒有被正確處理，不會被當成「檔案不存在」？
   - 有沒有把 `serve.mjs`、`scripts/` 自己這種「不該被快取」的檔案也算進去？
6. 最後才請 Claude 把 CLAUDE.md 的那條規則改成「新增、刪除或改名檔案後，執行 `node scripts/check-sw.mjs`，並把 `CACHE` 版本號加一」。要不要 commit 你自己決定（注意 `scripts/` 目錄在 GitHub Pages 上也會被公開，但裡面沒有秘密，沒關係）。

進階：把它設成 Stop hook，讓 Claude 每次說「完成了」之前都自動跑一次（做法參考 [W41 週報](../weekly/2026-W41.md) 的「完成的定義」）。

## 8. ⚠️ 風險與辨識：一個人、不到 100 字的指令，AI agent 入侵 100 多家公司

Reuters 10/19 報導，資安公司 NorForge 的研究員 Snorre Fagerland 發現一些**沒有設密碼、直接暴露在網路上的 Cairn 控制面板**。Cairn 是一個開源的 AI agent 編排平台。他透過這些面板，看到 agent 在做什麼：

- 攻擊從 **9/25** 開始，agent 嘗試入侵 **1,200 多個網站**，主要是美國、加拿大、澳洲、日本的線上商店；Reuters 點名的受害公司包括 Deere、SharkNinja、Cummins。
- 攻擊者給 agent 的指令**不到 100 個中文字**；估計每成功入侵一站約花 23 小時、$50 的 token，整個行動約 $5,000。NorForge 沒有實際的用量資料，這些金額只是估計。
- 有報導說使用的是 Claude Code 搭配 DeepSeek 模型（待確認）；Reuters 也無法確定有多少資料被偷。

（[Cybersecurity News](https://cybersecuritynews.com/chinese-hacker-use-ai-agent-to-hack/)、[ODSC](https://opendatascience.com/hacker-uses-ai-agents-to-breach-more-than-100-websites-for-5000/)、[WinBuzzer](https://winbuzzer.com/2026/10/20/hacker-used-ai-agents-to-breach-100-plus-companies-websites-xcxwbn)；Reuters 原文未取得，WinBuzzer 這次連不上，內容取自搜尋結果，待確認。）

這延續 [10/12 早報](2026-10-12.md) 南韓銀行被 AI agent 搭配 Claude Code 入侵的事件。差別是這次的規模：**同一個人同時打上千個目標**。

**辨識與防範**：

- **「小網站不會被盯上」已經不成立**：以前攻擊者要挑值得花時間的目標，現在一站 $50，所有暴露在網路上的服務都會被試。你部署在 GitHub Pages 的 price-tracker 是純靜態、沒有後端，風險很低；但 badminton-expense 的 Apps Script webhook 是公開的 URL，而且 GAS 的 `doPost` 讀不到 header、無法驗證 LINE 簽章（README 有寫），目前靠「只有已綁定的 userId 能記錄」防護。請 AI 改 `doPost` 時，要確認這道檢查不會被「簡化」掉。
- **別讓你自己的 agent 工具變成入口**：這次攻擊者會被發現，正是因為他的 Cairn 控制面板沒有密碼。你在本機或雲端開的 agent dashboard、MCP server、`serve.mjs` 這類開發伺服器，**不要綁在 `0.0.0.0` 或開公開 port**。用 Claude Code 的 Remote Control 或官方雲端 session，而不是自己把終端機暴露到網路上。
- **對「AI 幫我找漏洞」的 email 或私訊提高警覺**：同樣的工具也被拿來大量發送「我們掃到你網站有漏洞，付費就幫你修」的勒索信。先自己查證，不要點信裡的連結。
