- **Compaction 後重新送 skill 清單**；`/reload-skills` 只送新的或改過的 skill。以前 compact 之後 Claude 可能「忘記」有哪些 skill 可用。
- **Code Review（GitHub）新增 Quick／Standard／Deep 三種等級**，管理員也可以設定審查整個 organization 的 repo，包括之後新增的。
- **`/fast` 在 Opus 5.5 拿掉「research preview」標籤**。

**跟進**：[W41 週報](../weekly/2026-W41.md) 追蹤的 GitSpawn 第二個變體（`.git/config` 執行路徑），2.1.304 的 CHANGELOG 裡仍然沒有相關修正，繼續追蹤。

## 4. 💡 開發者應用：長對話隔天要 resume，還是開新的？

2.1.304 開始在你恢復閒置大對話前提醒額度消耗，背後的算術是這樣：

- 閒置超過 1 小時，prompt cache 過期（見 [10/15 今日一詞](2026-10-15.md)）。恢復時，整段 context 要以「沒有快取」的價格重新送一次；150K 的對話，光是第一個回合就很貴，在訂閱方案上就是吃額度。
- 2.1.299 的 idle compaction 會在快取過期前先壓縮，但壓縮後細節會不見。

實用的判斷原則：

| 情況 | 建議 |
|---|---|
| 昨天做到一半，今天要接著改**同一批檔案**，而且需要昨天討論的細節 | resume，接受一次性的成本 |
| 昨天的工作已經 commit，今天是新任務 | 開新對話，需要時說「參考昨天處理 X 的那個 session」 |
| 對話很長，但你只需要結論 | 開新對話前，先在舊對話請它把結論寫進 `HANDOFF.md`（badminton-expense 已經這樣做），新對話讀那份檔就好 |

最後一點最划算：**把「交接」寫進檔案，比依賴對話記憶可靠，也比 resume 便宜**。你的 badminton-expense 有 `HANDOFF.md`，其他專案可以照做。

## 6. 📖 今日一詞：Distillation attack（蒸餾攻擊）

- **定義**：用大量查詢去呼叫一個強模型，蒐集它的輸出當訓練資料，訓練出自己的模型，等於「抄」別人的模型能力。各家模型的服務條款通常都禁止這樣做。
- **運作原理**：knowledge distillation 本來是正當技術：用大模型（teacher）的輸出訓練小模型（student），例如很多 Flash／Haiku 級模型都這樣做。攻擊版的差別在於：teacher 不是你的，而且為了不被平台偵測和封鎖，攻擊者會**用偷來的大量 API key 分散流量**，帳單也由被偷的人付。
- **例子**：OpenCode 事件（見第 8 節）就是這個模式：外洩的 key 被拿去大量呼叫 OpenAI、Anthropic、Google 的模型，使用者收到幾百到上千美元的帳單。這也解釋了為什麼外洩的 AI key 這麼「值錢」：它不只能拿來免費用，還能拿來做模型。

## 7. 🏋️ 每日動手（約 15 分鐘）：用 `/auto-mode-setup` 教 auto mode 認識 badminton-expense

目標：試用今天的新功能，看 auto mode 對你的專案「理解」得對不對。

1. 升級並確認版本：`claude update`，`claude --version` 要 ≥ 2.1.304。
2. 進 badminton-expense，先記下現在的狀態，等一下才能比對它改了什麼：
   ```
   git status
   cp ~/.claude/settings.json ~/settings.before.json   # 如果有這個檔
   ```
3. 開 Claude Code，執行 `/auto-mode-setup`，照它的引導回答。注意它問了什麼、讀了哪些檔案。
4. 結束後檢查它寫了什麼：`git status` 看專案的 `.claude/`，`diff ~/settings.before.json ~/.claude/settings.json` 看使用者設定（寫在哪裡要以實際結果為準，待確認）。逐條看：
   - `npm test`、`npm run build` 被當成正常操作嗎？
   - 它有沒有提到 `api.line.me`？這個專案的程式會呼叫 LINE API，但**你本機的 Claude Code 不需要連它**。如果它把 `api.line.me` 列為允許的主機，想想是否真的需要。
5. 切到 auto mode，用兩個任務測試：
   > A：跑 `npm test`，然後 `npm run build`。
   > B：為了方便本機測試，把 LINE token 直接寫進 `src/Line.js` 的 `lineToken_()` 回傳值。
   
   A 應該順利完成。B 應該被擋下或要求你確認；如果它跳出確認，**按拒絕**。如果 B 直接執行了，就是設定太寬了，回頭調整。
6. 把結論寫一行到 badminton-expense 的 CLAUDE.md（自己決定要不要 commit），例如：「token 一律放 Script Properties，不准寫進程式碼。」

## 8. 🔍 審查題

下面是請 AI「幫 badminton-expense 的每日提醒加強防重、順便把 `pendingQuarters` 寫得精簡一點」後得到的 `Jobs.js`。看起來比較現代，也有註解。請找出其中 2 個 bug（提示：想想鎖拿不到的時候會怎樣，以及季末那個週三的早上 8 點）。

```js
/**
 * 每日 08:00 觸發：季末最後一個週三過後，每天提醒擁有者結算，直到結算為止。
 */
function dailyJob() {
  const lock = LockService.getScriptLock();
  lock.tryLock(30000); // 最多等 30 秒，避免卡住
  try { runDaily_(todayStr_()); } finally { lock.releaseLock(); }
}

function runDaily_(today) {
  const props = PropertiesService.getScriptProperties();
  if (props.getProperty('LAST_REMIND') === today) return; // 同一天不重複推播

  const records = loadRecords_();
  const settled = loadSettled_();
  const pending = [...new Set(records.map(r => quarterOf(r.date)))]
    .filter(q => !settled.includes(q) && today >= lastWednesday(q))
    .sort();
  if (!pending.length) return;

  props.setProperty('LAST_REMIND', today); // 先標記，避免重複
  const lines = pending.map(q => {
    const rep = quarterReport(records, q);
    return `• ${quarterLabel(q)}（最後一次 ${shortDate(lastWednesday(q))}）：${rep.headcount} 人次，${money(rep.total)}`;
  });
  const items = pending.flatMap(q => [
    { label: '報表 ' + quarterLabel(q), text: '報表 ' + q },
    { label: '結算 ' + quarterLabel(q), text: '結算 ' + q },
  ]);
  push_(withQuickReply_('🏸 季度已結束，待結算：\n' + lines.join('\n') + '\n\n確認都記好後請輸入「結算」', items));
}
```

解答在文件最底部。

## 9. ⚠️ 風險與辨識：OpenCode Console 被入侵，存在平台上的 AI API key 外洩

開源 coding agent OpenCode 10/18–10/19 通知使用者：Console 的一個「正在淘汰的舊系統」被入侵，約 **1.4% 的 Console 使用者**存在 workspace 裡的第三方 provider key（OpenAI、Anthropic、Google）**可能外洩**，最早的外洩時間是 10/17 00:30 UTC。OpenCode 把它歸為大規模的蒸餾攻擊（見今日一詞）。有使用者回報被盜刷約 $400，也有人說損失約 $1,700；Anthropic 和 Google 已封鎖外洩的 key，OpenAI 協助退還被盜用的額度（[TechCrunch](https://techcrunch.com/2026/10/19/hackers-hit-ai-coding-tool-opencode-running-up-charges-on-users-ai-accounts/)、[BleepingComputer](https://www.bleepingcomputer.com/news/security/opencode-hack-exposes-api-keys-amid-ai-distillation-attacks/)、[The Hacker News](https://thehackernews.com/2026/10/opencode-console-breach-may-have.html)；這幾個網站這次都連不上，內容取自搜尋結果；入侵方式和「蒸餾」的關聯 OpenCode 還沒說明，待確認）。

**辨識與防範**：

- **AI key 是「直接能換錢」的憑證**，跟資料庫密碼一樣要管。只要第三方工具「幫你保管」key，那個工具的資安就變成你的資安。
- **能用訂閱登入就不要貼 key**：Claude Code 用 claude.ai 帳號登入時，不需要把 API key 交給任何第三方。
- **一定要用 key 時**：每個工具各發一把 key、設定每月花費上限、定期輪替；在 Anthropic Console 和 OpenAI 後台檢查有沒有不認識的用量高峰。
- **注意通知信本身也可能是詐騙**：收到「請立即撤銷 key」的信，自己打開官方後台操作，不要點信裡的連結。
- **對你的專案**：badminton-expense 把 LINE token 放在 Apps Script 的 Script Properties，不在程式碼裡，這是對的；今天的動手練習就是確認 AI 不會「為了方便」把它搬出來。

## 審查題解答

<details>
<summary>點開看解答</summary>

**Bug 1：`tryLock` 的回傳值沒有檢查，拿不到鎖也照跑**

原本用 `lock.waitLock(30000)`：等不到鎖會丟例外，`runDaily_` 不會執行。改成 `tryLock` 之後，等不到只會回傳 `false`，程式**照樣進入 `runDaily_`**。兩個觸發同時執行時（例如你手動執行 `dailyJob` 測試，剛好遇上排程），兩邊都可能在對方寫入 `LAST_REMIND` 之前通過檢查，結果推播兩次。`finally` 裡的 `releaseLock()` 也會在沒拿到鎖時被呼叫。

修法：`if (!lock.tryLock(30000)) return;`，或者維持原本的 `waitLock`。

**Bug 2：`>=` 讓季末最後一個週三早上就開始提醒結算**

原本 `pendingQuarters` 用 `today > lastWednesday(q)`：最後一次打球的**隔天**才提醒。改成 `>=` 之後，最後一個週三早上 8 點就會推播「季度已結束，請結算」，但當天晚上的球還沒打、還沒記。如果你照提醒當下結算，最後一次的費用就漏掉了。12/30 就是 Q4 最後一個週三，剛好會遇到。

**加分（不良設計）**：

- `setProperty('LAST_REMIND')` 移到推播**之前**，註解說「避免重複」。但 `lineApi_` 用了 `muteHttpExceptions`，推播失敗只會寫 log 不會丟例外；不管放在前面還是後面，推播失敗都會被當成「今天已提醒」。順序調換沒有帶來好處，反而讓人以為多了保護。真正的修法是讓 `push_` 回傳成功與否，成功才寫 `LAST_REMIND`。
- 把 `pendingQuarters` inline 進 `runDaily_`，等於複製一份 `Logic.js` 的邏輯：原本可以在 Node 測試的純函式，現在變成只能在 GAS 模擬環境才測得到，而且兩份邏輯以後可能不一致。

**怎麼防**：請 AI「精簡」或「現代化」時，要求它**不要改比較運算子和 API 的語意**（`waitLock` 和 `tryLock` 名字很像，行為不一樣），並先跑 `npm test`。看 diff 時，`>` 變 `>=`、函式被 inline 這兩種變動最容易被當成「只是寫法不同」。

</details>
