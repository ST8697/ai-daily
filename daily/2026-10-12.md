## 1. 🛠️ Claude Code 更新

週末沒有新版本，目前最新仍是 **2.1.296**（[CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)；第三方報導說 10/9 發布，待確認）。`autoCompactWindow`、`CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL`、`/cost` 新價格和 hook debug log 已經在 [W41 週報](../weekly/2026-W41.md) 報過，下面只整理週報沒提到、但會影響工作方式的項目：

- **Edit 不再弄壞非 UTF-8 檔案**：以前 Edit／NotebookEdit 遇到 Windows-1252、Shift-JIS、GBK 這類編碼的檔案，會把所有非 ASCII 字元換掉；現在改成直接拒絕編輯。
  - **我可以怎麼用**：舊的 C#／.NET 專案常有 Big5 存檔的 `.cs`、`.config`，以前改完中文註解可能整份變亂碼。現在 Claude 會被擋下，這時請它先用 `iconv -f big5 -t utf-8` 轉檔、確認 diff 之後再改，不要讓它「想辦法繞過去」。
- **`--debug` 會指出自訂 agent frontmatter 的錯字**：`.claude/agents/*.md` 裡打錯的欄位（例如 `modle: haiku`）以前會被默默忽略，subagent 就照預設模型跑。現在 debug 輸出會列出無法辨識的欄位，並提示可能的正確拼法。
  - **我可以怎麼用**：上週建議把搜尋類 subagent 改成 `model: haiku`，改完後跑一次 `claude --debug`，確認設定真的有生效。今天的動手練習就是這個。
- **Read 新增 `allow_large`**：需要完整檔案而且 context 放得下時，Claude 可以一次讀完超過一般大小限制的文字檔，不用分段讀。大型 log、產生出來的 `dist/Code.gs` 這類檔案比較不會讀到一半就開始猜。
- **安全修正**：
  - Bash 權限檢查會自動核准某些「先設定 `BASH_ARGV0` 再使用它」的指令，現在改成要你確認。這是一個可以讓指令繞過 allow 規則的洞。
  - 分享出去的 transcript 和 debug log 在做 secret 遮蔽時，會漏掉某些值（例如 shell 字串裡的 JSON），已修正。
  - **我可以怎麼用**：如果你會把 transcript 或 `--debug` log 貼給別人看，請先更新到 2.1.296。
- **MCP 工具描述的預設上限從 2,048 提高到 4,096 字元**：描述比較長的 MCP server（例如有很多參數說明的資料查詢工具）比較不會被截斷，Claude 選錯工具的機率會降低。

## 4. 💡 開發者應用

- **把 subagent 的設定當成程式碼來驗證**：2.1.296 會在 `--debug` 指出 frontmatter 錯字，正好提醒我們：`.claude/agents/*.md` 寫錯一個欄位名稱不會報錯，只會「靜靜地照預設跑」。最可能出事的就是 `model`（以為用 Haiku 省錢，其實一直在用 Opus）和 `tools`（以為限制了工具，其實全開）。改完 agent 設定後，跑一次 `claude --debug` 加上 `/cost`，確認設定有生效，再去調整其他東西。
- **平行 agent 一定要用 worktree 隔開**：Codex 和 Claude Code 都把 worktree 做成內建工具，原因很實際：兩個 agent 在同一個工作目錄同時改檔、跑測試，會互相踩到對方的修改，而且出錯時很難追。實務上的做法是：**一個任務一個 worktree 和 branch，做完 merge 回來**；共用的 `node_modules` 或 build 輸出要注意，必要時每個 worktree 各自 install。
- **舊 .NET 專案先統一編碼再交給 AI**：Edit 現在遇到非 UTF-8 檔案會拒絕，與其每次撞到再處理，不如在專案裡一次把 `.cs`／`.config` 轉成 UTF-8（with BOM 或不帶 BOM，與團隊約定一致），並在 `.editorconfig` 寫上 `charset = utf-8`，在 CLAUDE.md 寫一行「所有檔案為 UTF-8」。

## 6. 📖 今日一詞：Git worktree

- **定義**：同一個 git repo 同時簽出多個工作目錄（working tree），每個目錄對應一個不同的 branch，但共用同一份 `.git` 物件資料庫。
- **運作原理**：`git worktree add ../repo-feat-x -b feat-x` 會建立一個新資料夾，裡面是 `feat-x` 分支的檔案，它的 `.git` 只是一個指向主 repo 的檔案。commit 和 branch 是共用的，但每個 worktree 有自己的 HEAD、index 和工作檔案。同一個 branch 不能同時被兩個 worktree 簽出，這個限制剛好可以防止兩個 agent 改到同一個分支。
- **例子**：你想讓一個 agent 替 price-tracker 加匯出 CSV，另一個 agent 修深色模式的配色。如果兩個都在主目錄裡做，一個在跑 `node serve.mjs` 測試時，另一個可能正在改 `css/style.css`，結果你分不清哪個改動造成哪個問題。改用兩個 worktree 各自做、各自 commit，最後再 merge。在 Claude Code 裡，subagent 設 `isolation: worktree` 就會自動這樣處理；Codex 0.162 起也能讓 agent 自己建 worktree。

## 7. 🏋️ 每日動手（約 10 分鐘）：替 badminton-expense 建一個 Haiku 測試 subagent，並用 `--debug` 抓設定錯字

badminton-expense 的 `npm test` 跑 `test/logic.test.js` 和 `test/gas-sim.test.js`。跑測試、讀失敗訊息、整理是哪個測試壞掉，這類工作很適合交給便宜的 Haiku。我們建一個專門跑測試的 subagent，並驗證它真的有用 Haiku。

> 在你自己電腦上的 badminton-expense 做（早報不會動你的 repo）。需要 Claude Code 2.1.296 以上。

1. 建立 `.claude/agents/test-runner.md`，**故意把 `model` 打成 `modle`**：
   ```markdown
   ---
   name: test-runner
   description: 執行 npm test 並回報失敗的測試名稱、錯誤訊息與可能的原因。改完 src/ 後使用。
   modle: haiku
   tools: Bash, Read, Grep
   ---
   在專案根目錄執行 `npm test`。全部通過就只回一行「✅ N/N 通過」。
   有失敗時，對每個失敗的測試列出：測試名稱、斷言訊息、對應的 src/ 檔案與行號、一句話推測原因。
   不要修改任何檔案。
   ```
2. 用 `claude --debug` 開一個 session，輸入「用 test-runner 跑一次測試」。在 debug 輸出裡找關於 `modle` 的警告，看它是否提示你應該是 `model`。
3. 把 `modle` 改回 `model`，重開 session 再跑一次，用 `/cost` 或 debug log 確認這次 subagent 用的是 Haiku。
4. 驗收：在 `src/Logic.js` 隨便改一個計算（例如把金額多加 1），再請 Claude「用 test-runner 檢查」。確認回報的格式符合你的要求，而且它**沒有自己去修**。最後記得把改動還原。
5. 加分：在 badminton-expense 的 CLAUDE.md 加一行「改完 src/ 後用 test-runner subagent 跑測試」，之後就不用每次提醒它。

## 9. ⚠️ 風險與辨識：AI agent 被拿來打銀行，而 session 紀錄讓攻擊者露出馬腳

CrowdStrike 10/8 的報告指出，9 月底到 10 月初，一名可能在中國廣東的攻擊者用開源 AI 滲透測試 agent **ARTEX**，搭配 Claude Code 等 LLM，對南韓多家金融機構發動攻擊並竊取客戶資料（[Reuters via TradingView](https://www.tradingview.com/news/reuters.com,2026:newsml_L1N45T11Q:0-south-korean-banks-were-likely-hacked-by-a-china-based-actor-with-an-ai-agent-crowdstrike-says/)、[Infosecurity Magazine](https://www.infosecurity-magazine.com/news/chinese-hacker-ai-korean-banks/)、[Taipei Times](https://www.taipeitimes.com/News/front/archives/2026/10/09/2003865655)）。新韓銀行表示約 2.5 萬名客戶個資外洩，各家報導的受害機構數量從 7 家到 9 家都有，正式歸因仍待確認。值得注意的是，CrowdStrike 是從攻擊者 **AI coding 工具的 session 內容**裡找到個人資訊，才推測出嫌疑人的身分。

**對開發者的兩個啟示**：
- **攻擊門檻降低了**：以前需要一個團隊花幾週做的偵察、寫 exploit，現在一個人加上 agent 就能做。你自己的小專案（例如部署成公開 Web App 的 Apps Script）被自動化掃描的機率只會更高：不要在程式碼裡寫死 token，查詢頁面不要露出不必要的個資。
- **session 紀錄是敏感資料**：你跟 Claude Code 的對話會留下路徑、帳號、內部網址，甚至貼進去的 token。攻擊者的紀錄可以用來抓人，你的紀錄外流時也一樣會洩漏你的資訊。分享 transcript 前請先更新到 2.1.296（修正了 secret 遮蔽漏洞），而且自己再看過一遍；不要把 `.env` 的內容直接貼進對話。
