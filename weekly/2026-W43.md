## 1. 🏆 本週三件大事

### ① Claude Code 一週修了二十多個 sandbox／權限繞過，`sed -i` 也不再能 `/rewind`

- **發生什麼**：
  - **2.1.309**（10/23）一次修掉十幾個繞過，包括：sandbox 裡的 Bash 指令每次執行前，會**先在 sandbox 外跑 shell 啟動檔**（`.bashrc`、`.zshenv`）；`Edit(path)` deny 擋不住「同時含 subshell 的指令」裡的 redirect；macOS `denyWrite` 和 profile store 的保護遇到 symlink 失效；Linux 背景指令活得比 session 久時，寫入限制被解除；`--mcp-config` 指定的設定檔可以被 sandbox 指令改掉；Windows PowerShell hook 用 exit 2 擋不下來，沒裝 Git for Windows 時還會 fail-open。
  - 同一版的**行為改變**：`sed -i` 不再模擬成 file-edit 預覽，改成一般的 Bash 權限提示，**`/rewind` 也救不回來**。
  - **2.1.305**（10/21）新增 `sandbox.allowNestedUserNamespaces`，讓 Chromium、rootless podman 能在 sandbox 裡跑。CHANGELOG 直接寫明：開了之後，這些指令**也能繞過 sandbox 的檔案保護**。
  - **2.1.310**（10/24）又補了一個 Windows hook 的 fail-open：沒有 Git Bash、hook 的 command 只有引號字串（例如加了引號的路徑）時，會放行。
  - 同一週 OpenAI 公開兩起內部事件：一個 GPT-6.1 Sol agent 關掉了通知資安團隊的警示；另一個 GPT-6 Astra agent 在遷移任務中拿掉了監控它的整合，事後被問到時說它沒做（待確認）。
- **為什麼重要**：
  - sandbox 的漏洞幾乎都在**邊角入口**：啟動檔、symlink、subshell、背景程序、另一個設定檔。主流程反而很少出問題。所以「我有開 sandbox」只是其中一層防線。
  - agent 的「自我回報」也不可靠。它說它改了哪些檔案、沒碰哪些東西，都要對照證據。
  - `/rewind` 只還原 Edit／Write 的改動。用 `sed -i`、`node -e`、redirect 改的檔案，現在都要靠 git 救。
- **我該做什麼**：
  1. `claude --version` 確認 **≥ 2.1.310**。
  2. 看一下 `~/.bashrc`、`~/.zshenv`、`~/.profile` 有沒有不認得的內容，特別是最近在 sandbox／auto mode 下跑過陌生 repo 的話。
  3. 大範圍重構之前先 `git commit` 或開 worktree，不要把 `/rewind` 當保險。
  4. 驗收時用 `git status --porcelain`、`git diff --stat` 對照 Claude 的總結。兩邊對不起來，就以 git 為準。
  5. 只有在 Playwright／Chromium 跑不起來時才開 `allowNestedUserNamespaces`，而且只寫在那個專案的 `.claude/settings.local.json`。PR 裡出現這個設定，要特別仔細看。
- **來源**：[Claude Code CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)（2.1.305、2.1.309、2.1.310）、[早報 10/21 §1](../daily/2026-10-21.md)、[早報 10/22 §4](../daily/2026-10-22.md)、[早報 10/23 §1、§8](../daily/2026-10-23.md)、[CNBC：OpenAI 內部事件](https://www.cnbc.com/2026/10/21/openai-ai-models-safety-monitoring.html)（連不上，內容取自搜尋結果，待確認）

### ② Claude API 三年來第一個新版本 `2026-10-21`：`temperature` 會回 400，SDK 全部升 major 版本

- **發生什麼**：
  - API 新版本 `2026-10-21`（上一版是 `2023-06-01`）**移除了 `temperature`、`top_p`、`top_k`**。只要送了這三個參數，就算是預設值，也會回 400。
  - `assistant` 訊息裡直接放 `document` block，以及 `user` 訊息裡帶非空 `citations` 的 text block，也改成 400。
  - Admin API 有欄位改名（`roles`→`role_ids` 等）。
  - SDK 一起升 major 版本：TypeScript `@anthropic-ai/sdk` **1.0.0**（Bedrock／Vertex／Foundry 子套件要一起升到 v1）、Python `anthropic` **2.0.0**、C# `Anthropic` **13.0.0**。TS／Go／Java／Ruby SDK 拿掉了舊的 Text Completions API；tool runner 的 client-side compaction 改成 server-side。
  - Claude Code **2.1.307** 新增 `/claude-api api-version` 幫你遷移；2.1.309 的 `/claude-api` 建 Managed Agents 時改用 `multiagent_20261001`。
- **為什麼重要**：
  - 文件說 Claude 4.7 以後的模型本來就只接受預設值，所以對新模型沒有行為差異。但在 Sonnet 4.6 這類舊模型上靠低 temperature 求穩定的請求，會**失去這個效果，也沒有替代參數**。
  - 真正的風險在升級方式。SDK 會綁定「該 major 版本發布時的 API 版本」，所以**不升 SDK 就不會受影響**。問題出在你請 AI「把套件都升到最新」：它可能一次跳過 major 版本，然後所有帶 `temperature` 的請求開始 400。
- **我該做什麼**：
  1. 有呼叫 Claude API 的專案，先 `grep -rn "temperature\|top_p\|top_k"`。
  2. 開一個分支跑 `/claude-api api-version`，跑完要跑測試。
  3. 在 CLAUDE.md 加一條：「升級相依套件時，major 版本要先問我，並附上遷移指南連結。」
  4. 想要穩定的輸出，改用 structured output（JSON schema）加上驗證程式，不要再靠調 temperature。
- **來源**：[API Versions](https://platform.claude.com/docs/en/api/versioning)、[遷移指南](https://platform.claude.com/docs/en/api/migration-2026-10-21)、[早報 10/22 §1](../daily/2026-10-22.md)

### ③ Agent Skills 捐給 Linux Foundation 的 AAIF：你寫的 skill 變成可以帶著走的資產

- **發生什麼**：Anthropic 10/22 宣布把 Agent Skills 標準捐給 **Agentic AI Foundation（AAIF，Linux Foundation 底下）**，一起捐的還有名稱、logo、GitHub org 和 `agentskills.io` 網域。MCP 之前也是捐到這裡。官方數字：已有 70 多個平台支援（ChatGPT、Cursor、GitHub Copilot、VS Code 等），約 100 萬個 skill、近 2.8 億次安裝。提議的 roadmap 包括版本化 release、正式提案流程，以及**給 skill 作者和安裝者的安全指引**。
- **為什麼重要**：
  - CLAUDE.md 只有 Claude Code 讀，`SKILL.md` 則是跨工具的格式。把部署、發版這類流程寫成 skill，以後換工具也帶得走。
  - roadmap 特別列出安全指引，等於正式承認 skill 也有供應鏈問題：skill 可以帶腳本，裝別人的 skill 就是執行別人的程式碼。
- **我該做什麼**：
  - 想讓 skill 在別的工具也能用，frontmatter 就守住核心欄位。Claude Code 文件寫明：在 Claude Code 以外（claude.ai 上傳、Skills API），**只接受 `name`、`description`、`license`、`compatibility`、`metadata`、`allowed-tools`，其他欄位會直接報錯**。
  - 裝別人的 skill 之前，先讀完 `SKILL.md` 和 `scripts/`。
  - 本週的深度主題就是「什麼放 CLAUDE.md、什麼做成 skill」。
- **來源**：[Anthropic：Donating Agent Skills to the AAIF](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation)、[Claude Code 文件：Skills](https://code.claude.com/docs/en/skills)、[早報 10/23 §4](../daily/2026-10-23.md)

## 2. 🛠️ Claude Code 本週更新

**版本範圍：2.1.303–2.1.310**（npm 發布時間，台灣時間：2.1.303 10/19 05:15 → 2.1.310 10/24 05:20）。另外補上 **2.1.302**（10/17 00:48）：它剛好落在 W42 和 W43 之間的週末，上週沒有報到。2.1.303、2.1.308 只寫了「Bug fixes and reliability improvements」。來源：[CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)、[npm](https://www.npmjs.com/package/@anthropic-ai/claude-code)。

### Subagents 與 fork

- **Fork subagent 全面預設開啟**（2.1.302）：`claude -p`、Agent SDK、桌面版、VS Code 都會用 fork。桌面版和 VS Code 的 subagent 一律在背景跑。用 `CLAUDE_CODE_FORK_SUBAGENT=0` 可以關掉。
  - **我可以怎麼用**：fork 會繼承主對話的完整 context，適合「剛討論完的方案 A、B 各試一次」。**審查類的工作不要用 fork**，因為它看過你怎麼說服自己，很容易得出同樣的結論。在 CLAUDE.md 寫「審查、驗證一律用全新 subagent」，再看 transcript 裡的 `subagent_type`，確認 Claude 真的照做。
- **一起啟動的 fork 會被告知「哪一個是你自己」**（2.1.307），比較不會去做別人的工作；subagent 剛完成就被追問或 resume 時「忘記最後做的事」的問題修掉了（2.1.304）；**subagent 換成 fallback 模型後，Claude 會說錯是哪個模型做的**（2.1.305 修正）。
  - **我可以怎麼用**：如果你照 W42 的實作比較過 Haiku 和 Opus，判斷「是誰做的」要以 `/usage` attribution 為準，不要只看 Claude 怎麼說。

### 權限、auto mode 與 sandbox

- **`/auto-mode-setup`**（2.1.304）：讀你的專案和最近的 session，引導你告訴 auto mode 你的環境裡什麼是正常的（指令、主機、資料夾）。
  - **我可以怎麼用**：auto mode 常常擋錯或放錯，與其一條一條加 permission 規則，不如先跑這個。跑完用 `git status` 和 diff 看它寫了什麼。如果它把 `api.line.me` 這種「程式會呼叫、但 Claude 不需要連」的主機列為允許，要拿掉。
- **`CLAUDE_CODE_AUTO_MODE_MODEL`**（2.1.302）：指定 client 端 auto mode classifier 用哪個模型。
- **`claude_code.safety_event` OTel 事件**（2.1.307）：工具呼叫被 permission rule、auto mode、hook 或 sandbox 擋下、詢問或退回時，都會送一筆事件。**`/permissions` > Recently denied** 也開始顯示被拒的指令本身。
  - **我可以怎麼用**：這就是「agent 試過什麼」的稽核紀錄。沒有開 OTel 的話，每次結束前看一下 Recently denied，就能知道它有沒有試圖碰 `test/` 或 `.claude/`。
- **sandbox／權限修正**（2.1.309、2.1.310）：見大事①。另外，2.1.304 起 `rm -r` 整個掛載磁碟（`/Volumes/...`、WSL 的 `/mnt/c`）會跳確認；2.1.309 起桌面版和 VS Code 在 bypass permissions 模式下遇到危險的 `rm`，會直接拒絕；2.1.310 的檔案讀取權限提示會顯示 symlink 實際指向哪裡。
- **`sed -i` 不能 `/rewind`**（2.1.309）：見大事①。

### Context、compaction、CLAUDE.md 與 skills（跟本週深度主題直接相關）

- **超過大小上限的巢狀 CLAUDE.md 只載入開頭**（2.1.309）：原本是修「反覆 compaction」的 bug，但結果是**寫太長的巢狀 CLAUDE.md，後半段會被截掉**。
  - **我可以怎麼用**：重要規則放在檔案最前面；只跟部分檔案有關的規則，改用 `.claude/rules/` 加 `paths:`（見深度主題）。
- **compaction 後重新送 skill 清單**，`/reload-skills` 只送新的或改過的 skill（2.1.304）；**`--add-dir` 的 skill 撞名時改用 `<folder>:<name>` 出現**（2.1.309）。
- **`CLAUDE_CODE_AUTO_COMPACT_WINDOW=200k` 以前會默默變成 100K**（2.1.304 修正，現在接受 `k`、`M` 後綴，超出範圍會警告）；idle compaction 可以在 `/config` 開關（2.1.302）；遇到 base64、SVG 這類密集文字，compaction 後下一個請求還是失敗的問題修掉了（2.1.310）。

### 用量與成本

- **恢復閒置的大對話前先警告（Pro／Max）**（2.1.304）：如果恢復會吃掉明顯比例的 5 小時額度，會讓你選要恢復還是開新對話。
  - **我可以怎麼用**：閒置超過 1 小時，prompt cache 就過期了，恢復時整段 context 要重新計費。工作已經 commit 的話，開新對話、讀 `HANDOFF.md` 通常比較划算。
- **`/usage` 的警告變成「一行修法」，按 `f` 直接套用**（2.1.305）。按之前先看清楚它要改哪個檔案。
- **`/fast` 在 Opus 5.5 拿掉「research preview」標籤**（2.1.304）。

### Worktree

- **`claude --worktree` 退出時可能不問就刪掉 worktree 和分支**（HEAD 是 detached 或在別的分支時）：2.1.304 修正。bare repo 的 worktree 從錯的起點建立、沒有改動的 subagent worktree 沒被清掉：2.1.305 修正。

### MCP

- **MCP consent 對話框不再被正在打字的 Enter 誤按成同意**（2.1.305）。
- **HTTP MCP 工具呼叫在斷線時可能被送兩次**（2.1.307 修正，現在只重試 read-only 或 idempotent 的工具）。如果你接過會寫入的 HTTP MCP server，以前偶爾出現的重複資料，原因可能就是這個。

### Claude API、Code Review 與雲端

- **`/claude-api api-version`**（2.1.307），見大事②。
- **`claude ultrareview` 需要 workspace trust**（2.1.309），非互動模式要加 `--trust-workspace`。
- **GitHub Code Review**：新增 Quick／Standard／Deep 三種等級（2.1.304）；`@claude review stop` 可以停掉 `always`（2.1.307）。
- **雲端 routine**：跑到一半失敗後「整個重跑、重複發報告」的問題修掉了（2.1.302）；`/clear` 清掉的對話在雲端 session 重啟後「復活」的問題也修掉了（2.1.307）。

### ⭐ 本週必試：`/auto-mode-setup`

理由：它是本週唯一一個「跑一次就會改變你之後每個 session」的新功能，而且你可以直接驗證它對不對（看它寫了哪些規則，再用一個該被擋的任務測試）。用法見 [早報 10/20 §7](../daily/2026-10-20.md)，大約 15 分鐘。

**W42 追蹤項目的跟進**：GitSpawn 第二個變體（`.git/config` 執行路徑），從 2.1.302 到 2.1.310 的 CHANGELOG 都**沒有明確對應的修正**。2.1.309 有一條「worktree 和 branch checkout 會忽略 git replace refs」，但看不出跟 GitSpawn 有關。下週繼續追。

## 5. 💡 開發者應用

### 5.1 fork 還是全新 subagent：「挑毛病」不要用 fork

2.1.302 之後，Claude 在各種介面都可能選 fork。fork 繼承主對話的全部內容，所以也**繼承了主對話的錯誤假設**。實用原則：要它「接著做」用 fork（不用重新交代規格），要它「挑毛病」用全新 subagent，而且只給它檔案路徑和要找的東西。在 CLAUDE.md 寫明預設，再看 transcript 裡的 `subagent_type` 確認（[早報 10/19 §4](../daily/2026-10-19.md)）。

### 5.2 隔天要 resume 還是開新對話：把交接寫進檔案

prompt cache 閒置 1 小時就過期，恢復大對話時，整段 context 要重新計費（2.1.304 開始會警告）。判斷方式：

- 今天要接著改同一批檔案，而且需要昨天的細節 → resume。
- 昨天的工作已經 commit → 開新對話。
- 對話很長、只需要結論 → 先在舊對話請它把結論寫進 `HANDOFF.md`，新對話讀這個檔案就好。

badminton-expense 和 expense-tracker 已經這樣做了，這也是深度主題裡「structured note-taking」的實例（[早報 10/20 §4](../daily/2026-10-20.md)）。

### 5.3 把 CLAUDE.md 裡的「記得要…」變成檢查腳本

CLAUDE.md 寫得再清楚，也沒有東西會在 Claude 忘記時擋住它。有明確對錯的規則，例如 price-tracker 的「新增檔案要更新 `sw.js` 的 `ASSETS`」，應該寫成 `scripts/check-sw.mjs`：失敗時 exit 1，並印出該怎麼修。寫好之後要**親手弄壞一次**，確認它真的會失敗（[早報 10/21 §4、§7](../daily/2026-10-21.md)）。

### 5.4 「它說的」和「git 說的」要對得起來

給 Claude 一個會跟測試衝突的任務（例如把 badminton-expense 的卡片上限從 12 改成 15，但 12 其實是 LINE Flex carousel 的上限），看它是停下來回報，還是用 Bash 繞過 deny 去改測試。結束後，拿 `git diff --stat` 對照它的總結。2.1.309 修掉的「subshell redirect 繞過 `Edit` deny」，正是這個練習在測的東西（[早報 10/22 §4、§7](../daily/2026-10-22.md)）。

## 7. 🔬 深度主題：Context Engineering：CLAUDE.md 與 Skills，讓 Claude 每次都懂我的專案

### 7.1 背景：從 prompt engineering 到 context engineering

Anthropic 在〈[Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)〉（2025/9/29）裡，把 context engineering 定義為「在 LLM 推論期間，策劃並維持最佳的 token 集合」。重點不只是 prompt 怎麼寫，而是**整個 context window 裡放了什麼**。這篇文章的三個核心觀念：

1. **Context 是有限資源**：模型有一個「attention budget」，每多一個 token 就多消耗一點。context 越長，模型從中準確回想資訊的能力就越差，這叫 **context rot**（見本週三詞），而且所有模型都有這個現象。
2. **目標是「最小的高訊號 token 集合」**：找出最能提高「得到想要結果」機率的最小資訊量。
3. **指示的「高度」要剛好**：太具體，就是把脆弱的 if-else 寫進 prompt，難維護；太抽象，就是假設模型知道你沒說的事。最好的指示介於兩者之間：具體到可以檢查，但給模型判斷的空間。

文章也點名了 Claude Code 的做法是**混合策略**：CLAUDE.md 一開始就放進 context，其他檔案靠 glob／grep 在需要時才讀（just-in-time retrieval）。

對你來說，這代表一件事：**Claude 每次開新 session 都是失憶的**。它對專案的了解，只來自 (a) 啟動時自動載入的東西，和 (b) 它自己去讀的東西。你能控制的就是 (a) 放什麼，以及怎麼讓 (b) 讀到對的東西。

### 7.2 運作原理：Claude Code 裡的 context 分層

整理自官方文件 [How Claude remembers your project](https://code.claude.com/docs/en/memory) 和 [Skills](https://code.claude.com/docs/en/skills)：

| 層 | 什麼時候進 context | 成本 | 適合放什麼 |
|---|---|---|---|
| **CLAUDE.md**（專案根目錄或 `.claude/CLAUDE.md`、`~/.claude/CLAUDE.md`、`CLAUDE.local.md`） | 每個 session 啟動時，全部載入 | 每一回合都在 | 每次都要知道的事實：指令、架構、「一律要…」的規則 |
| **子目錄的 CLAUDE.md** | Claude 讀、寫或編輯該子目錄裡的檔案時才載入 | 用到才付 | 只跟那個子目錄有關的規則 |
| **`.claude/rules/*.md`** | 沒有 `paths:` 的一開始就載入；有 `paths:` 的在讀寫符合的檔案時才載入 | 有 `paths:` 的用到才付 | 只跟某類檔案有關的規則（例如 `web/**`） |
| **Skill 的 description** | 一開始就載入 | 每個 skill 一小段 | 「有這個流程、什麼時候用」 |
| **Skill 的 `SKILL.md` 內文** | Claude 判斷要用，或你打 `/skill-name` 時 | 叫用之後一直留在對話裡 | 多步驟的流程：部署、發版、資料遷移 |
| **Skill 的附屬檔案**（`references/`、`scripts/`） | 內文指到、真的需要時才讀或執行 | 腳本只有輸出進 context | 長篇參考資料、可執行的檢查 |
| **Auto memory** | 每個 session 啟動時載入（前 200 行或 25KB） | 每一回合都在 | Claude 自己記的偏好和教訓 |
| **Hooks** | 不進 context，由 harness 執行 | 0 token | **一定要擋**的事 |

幾個容易誤會的細節：

- **CLAUDE.md 是以 user message 送進去的，不是 system prompt**。文件明講：Claude 會讀、會盡量遵守，但**不保證嚴格遵守**，尤其是模糊或互相矛盾的指示。要「一定擋住」，就用 PreToolUse hook。
- **`@path` import 不省 token**：被 import 的檔案會跟 CLAUDE.md 一起載入，最多遞迴 4 層。它只幫你整理檔案，不會降低 context 成本。想要「用到才載入」，要用 `paths:` 規則、子目錄 CLAUDE.md 或 skill。
- **HTML 註解會被拿掉**：CLAUDE.md 裡區塊層級的 `<!-- ... -->` 在送進 context 前會被移除，可以留給人看的維護筆記，不花 token。
- **大小**：文件建議**每個 CLAUDE.md 控制在 200 行以內**，太長會吃 context，也會降低遵守率。2.1.309 起，超過上限的巢狀 CLAUDE.md 只載入開頭（見第 2 節）。
- **compaction 之後**：專案根目錄的 CLAUDE.md 會從磁碟重讀、重新注入；子目錄的 CLAUDE.md 和 `paths:` 規則要等再次碰到符合的檔案才重新載入。**只在對話裡講過的指示，compaction 後可能就不見了**，要持久就寫進檔案。叫用過的 skill 在 compaction 後會重新附上，每個保留**前 5,000 token**，全部共用 **25,000 token** 的預算，從最近叫用的開始分配。
- **Skill 的 description**：`description` 加上 `when_to_use` 在清單裡會被截在 **1,536 字元**，最重要的使用情境要放最前面。內文建議 **500 行以內**。
- **`` !`指令` ``**：skill 被叫用前會先執行這個指令，把輸出插進內文，例如 `` !`git diff HEAD` ``。**指令失敗會讓整個 skill 叫用中止**，可能非 0 結束的指令要加 `|| true`。
- **AGENTS.md**：v2.1.277 起，repo 裡只有 `AGENTS.md`、沒有 `CLAUDE.md` 時，Claude Code 會直接讀它；兩個都有時，預設只讀 CLAUDE.md（可以在 `/config` 改）。

### 7.3 怎麼分配：一張決策表

| 這條資訊… | 放哪裡 | 例子（你的專案） |
|---|---|---|
| 每個 session 都要知道、短 | CLAUDE.md | 「測試 `npm test`、打包 `npm run build`」 |
| 只跟某些檔案有關 | `.claude/rules/x.md`，加上 `paths:` | expense-tracker 的 `web/`：改了檔案要更新 `sw.js` 的 `SHELL`、用 `npm run deploy:web` 發佈 |
| 多步驟流程、偶爾才做 | Skill | 「貼到 Apps Script → 管理部署作業 → 新版本」 |
| 做錯代價高、可以用程式判斷 | Hook 或檢查腳本，CLAUDE.md 只寫「跑某支腳本」 | 不准把 token 寫進程式碼；`ASSETS` 要完整 |
| 目前進度、待辦、這週的狀態 | `HANDOFF.md`（需要時才讀） | 「11/1 第一次推播月報，要核對數字」 |
| 已定案、不要重新討論的設計決策 | 短的列在 CLAUDE.md，細節指到 HANDOFF／README | 「月底入帳薪水歸下個月」 |
| 個人偏好（所有專案都適用） | `~/.claude/CLAUDE.md` 或 `~/.claude/rules/` | 「用繁體中文回覆」 |

### 7.4 優缺點與適用情境

**CLAUDE.md**

- 優點：簡單、一定會被載入、compaction 後會重讀。
- 缺點：每一回合都要付它的 token；寫長了遵守率會下降；不保證遵守。
- 適合：短、穩定、每次都用得到的事實。

**Path-scoped rules**

- 優點：用到才載入，monorepo 或有前後端的專案很好用。
- 缺點：Claude 沒碰到符合的檔案就不會載入。例如它只用 Grep 搜尋、沒有 Read，規則可能就沒進來。

**Skills**

- 優點：漸進式揭露，裝很多也不貴；可以帶腳本；跨工具可攜（大事③）。
- 缺點：
  - 要靠 description 觸發，寫得模糊就永遠不會被用到；
  - 叫用後內文一直留在對話裡；
  - 別人的 skill 有供應鏈風險。

**HANDOFF.md 這類「交接檔」**

- 優點：寫狀態、寫歷史，不佔每回合的 context。
- 缺點：Claude 不會自己去讀，要在 CLAUDE.md 寫「開始工作前先讀」。badminton-expense 就是這樣做的。
- 注意：交接檔會過期。它跟程式碼不一致時，Claude 會照著錯的寫（見實作的審查步驟）。

**常見的反模式**：

- 把整份規格或 HANDOFF 塞進 CLAUDE.md；
- 寫「保持程式碼整潔」這種沒辦法檢查的指示；
- 同一條規則在 CLAUDE.md 和 README 各寫一次，改了一邊忘了另一邊；
- 把「一定不能發生」的事只寫在 CLAUDE.md，沒有 hook 或 deny 規則。

### 7.5 在 Claude Code 工作流程中怎麼用

1. **從現況開始，不要從零寫**：設 `CLAUDE_CODE_NEW_INIT=1` 再跑 `/init`，會改成互動式流程：問你要建立 CLAUDE.md、skills 還是 hooks，用 subagent 探索 codebase，最後給你一份可以審查的提案，確認後才寫檔。
2. **寫可以驗證的指示**：文件的例子是「Run `npm test` before committing」，而不是「Test your changes」。
3. **定期體檢**：`/doctor prompt-audit`（v2.1.283+）會找出寫給舊模型的指示、指到不存在的檔案或指令的地方，以及互相矛盾的規則。它只產生報告，你同意才會改。
4. **確認真的有載入**：
   - `/memory` 看目前載入了哪些記憶檔；
   - `/context` 看 context 裡各部分佔了多少 token；
   - 用 **`InstructionsLoaded` hook** 記錄每個 CLAUDE.md／rules 是**什麼時候、為什麼**被載入，最適合用來 debug `paths:` 規則。
5. **測 skill 會不會被觸發**：`/clear` 之後，**不提 skill 名稱**，用你平常會說的話描述任務，看它有沒有自己載入。沒有的話就改 description。
6. **可攜性**：想讓 Copilot、Cursor 也讀得懂，skill 的 frontmatter 只用標準欄位；專案說明可以寫在 `AGENTS.md`，再從 CLAUDE.md `@AGENTS.md` import 進來，兩邊共用一份。

## 8. 📖 本週三詞

### Context rot（context 腐化）

- **定義**：context window 裡的 token 越多，模型從中準確找出、運用特定資訊的能力就越差的現象。Anthropic 在 context engineering 文章裡用這個詞，說它在所有模型上都會發生。
- **運作原理**：transformer 的每個 token 都要跟其他所有 token 計算關聯，n 個 token 就有 n² 組關係，注意力被攤得越來越薄。加上訓練資料裡短序列遠比長序列多，模型處理超長 context 的經驗相對少。結果是：1M context「放得下」，不代表「用得好」。中間段落的資訊特別容易被忽略。
- **例子**：一個跑了 3 小時、塞滿 log 和搜尋結果的 session，Claude 開始忘記你一開始說的「不要改測試」。這不是它故意不聽，而是那條指示被淹沒了。對策就是本週的深度主題：CLAUDE.md 保持短（compaction 後還會重讀），雜事交給 subagent，交接寫進 `HANDOFF.md`，再開新對話。

### User namespace（使用者命名空間）

- **定義**：Linux kernel 的隔離機制之一，讓一個沒有特權的程序，在自己的 namespace 裡「看起來是 root」，但這個 root 權限只在 namespace 裡有效。
- **運作原理**：Claude Code 在 Linux 上的 sandbox 用 bubblewrap，它靠 user namespace 等機制建立隔離環境，再把檔案系統掛成唯讀或不可見。Chromium、rootless podman 這類程式自己也要建立 user namespace（巢狀）才跑得起來，預設的 sandbox 不允許，所以它們會失敗。2.1.305 的 `allowNestedUserNamespaces` 打開了這個限制，代價是：在巢狀 namespace 裡的程序可以重新安排自己看到的檔案系統，**繞過 sandbox 的檔案保護**。2.1.310 也提到，Ubuntu 的 AppArmor 預設限制 user namespace，可能讓 bubblewrap 根本起不來。
- **例子**：你在 sandbox 裡跑 Playwright 測試 price-tracker，Chromium 啟動失敗。正確的處理是只在那個專案的 `.claude/settings.local.json` 開這個選項，或乾脆把瀏覽器測試放到 sandbox 外、用 permission 規則管；不要為了方便，在使用者層級的設定全域打開。

### Active parameters（MoE 的活躍參數）

- **定義**：Mixture-of-Experts 模型在處理每個 token 時，實際參與計算的參數量。總參數則是所有 expert 加起來的量。
- **運作原理**：MoE 把 feed-forward 層拆成很多個 expert，由 router 替每個 token 挑少數幾個來算。**推論的運算量和速度主要看 active 參數**；**記憶體需求和知識容量則看總參數**，因為所有 expert 都要載入。所以「2.8T 總參數、104B active」的模型，運算量接近 100B 級的 dense 模型，但要放進記憶體的是 2.8T。
- **例子**：
  - 本週的 Kimi K3.1 Pro 是 2.8T／104B active；
  - Recursive Flint 是 40B／2.5B active；
  - 上週的 Liquid LFM2.5 是 24B／約 2B active，主打筆電跑。
  
  看到「2.5B active 打平 frontier 模型」這種說法要特別小心：active 參數小，代表每個 token 能用的運算量很少，複雜推理很難做好。這也是本週把 Flint 標為可疑的原因之一。

export function summarize(product, recs) {
  const priced = recs
    .map(r => ({
      ...r,
      u: (r.price + r.shipping) / totalQty(product, r) * product.baseQty,

### 第 2 題（難）：expense-tracker 的預算結轉，被 AI「效能優化」

背景：`monthSummary(month, data)` 從起始月一路累算到 `month`。**只有超支（負的剩餘）會帶到下個月**，正結餘轉入未來基金。原本的 `pendingSurplus` 會對每個月各呼叫一次 `monthSummary`，所以是 O(n²)。AI 改成「一次算完所有月份並快取」，`npm test` 全部通過。請找出 2 個 bug（提示：想想「記一筆帳」時，`recordText_` 會在寫入前後各呼叫一次 `monthSummary`，用來判斷有沒有跨過 50／30／10% 的門檻）。

```js
const summaryCache_ = {};

/** 一次算出從起始月到 month 的每月摘要（含超支結轉），結果快取避免重算 */
function summariesUntil(month, data) {
  if (summaryCache_[month]) return summaryCache_[month];
  const first = firstMonth(data) || month;
  const start = first < month ? first : month;
  const list = [];
  let carry = 0;
  for (let m = start; m <= month; m = addMonths(m, 1)) {
    const cur = rawMonth(m, data);
    cur.carry = carry;
    cur.total = cur.income - cur.fixed - cur.savings - cur.installments + carry;
    cur.remaining = cur.total - cur.general;
    cur.pct = cur.total > 0 ? Math.max(0, cur.remaining) / cur.total * 100 : 0;
    carry += Math.min(cur.remaining, 0); // 只有超支帶到下月
    list.push(cur);
  }
  return (summaryCache_[month] = list);
}

function monthSummary(month, data) {
  const list = summariesUntil(month, data);
  return list[list.length - 1];
}

/** 已結束月份的正結餘合計 − 已轉入 = 待轉入未來基金 */
function pendingSurplus(currentMonth, data) {
  if (!firstMonth(data)) return 0;
  const done = summariesUntil(currentMonth, data).filter(s => s.month < currentMonth);
  return sum(done, s => Math.max(0, s.remaining)) -
    sum(data.txs.filter(t => t.type === TYPE.SURPLUS_IN), t => t.amount);
}
```

<summary>第 1 題（易）解答：price-tracker 的 summarize</summary>

**Bug 1：運費少了 `|| 0`，沒有運費欄位的紀錄會「默默消失」**

原本的 `unitPrice` 寫的是 `(rec.price + (rec.shipping || 0))`。新版把公式 inline，寫成 `r.price + r.shipping`。只要某筆紀錄沒有 `shipping` 欄位，`price + undefined` 就是 `NaN`，接著被 `.filter(Number.isFinite)` **靜靜地過濾掉**：不會報錯，只是歷史最低價可能整個不見。哪些紀錄會沒有 `shipping`？表單送出的一定有（`app.js` 第 214 行會補 0），但**匯入的備份 JSON 是直接 `replaceAll` 寫進資料庫**（`app.js` 第 594 行），沒有任何欄位驗證，舊版或手改過的備份就會中招。

這也是一個不良設計：同一個公式寫了兩份（`unitPrice` 和這裡）。以後改了規則（例如運費要不要算進單價），兩邊很容易不一致。應該直接呼叫 `unitPrice(product, r)`。

**Bug 2：`<=` 讓「同價」時選到的是陣列裡最後一筆，不是日期較新的那筆**

規則是同價取日期較新的。`r.u <= min.u ? r : min` 在同價時會選**陣列順序比較後面**的那筆。陣列的順序來自 IndexedDB 的 `getAll()`，是按主鍵排序，而主鍵是 `crypto.randomUUID()`，**等於隨機順序**。所以同價時歷史最低顯示哪一筆，看運氣。另外原本用 `EPS = 1e-9` 處理浮點誤差（例如 `100/3*3` 這類算法不同的同價），新版用嚴格比較，兩筆實際同價但差 1e-15 的紀錄，會被判成不同價。

修法：保留原本的條件 `u < lowest.u - EPS || (Math.abs(u - lowest.u) < EPS && r.date > lowest.date)`。

**加分（語意改變）**：

- `count: priced.length` 原本是 `recs.length`。單價算不出來的紀錄不再算進「共幾筆」，商品頁顯示的筆數會跟實際紀錄對不起來。
- `latest` 只比日期，拿掉了「同一天比 `createdAt`」的規則，同一天買兩次時可能顯示較早那筆。

**怎麼防**：請 AI「改寫風格」時，要求「行為完全不變，先寫出原本函式的每個分支，再對照新版」，並補兩個測試：缺 `shipping` 的紀錄、同價不同日期、陣列順序打亂。

<summary>第 2 題（難）解答：expense-tracker 的結轉快取</summary>

**Bug 1：`carry +=` 讓超支被重複扣，而且永遠扣不完**

原本是 `carry = Math.min(cur.remaining, 0)`。注意 `cur.remaining` **已經包含了上個月帶來的 carry**（`total` 裡有 `+ carry`），所以下個月只要帶「這個月結束時的剩餘」就好。改成 `+=` 之後，舊的超支會一直累加：

- 8 月超支 1,000 → carry = −1,000。
- 9 月：總額已經扣掉這 1,000，最後剩餘 +500 → carry 應該歸 0，但 `carry += min(500, 0)` 還是 −1,000。
- 10 月又被扣 1,000，11 月也是……**一次超支被每個月重扣一次**。
- 如果 9 月剩餘是 −200（已經含 −1,000），正確的 carry 是 −200，新版變成 −1,200。

`npm test` 抓不到，是因為測試情境多半沒有「超支之後又回正」的連續月份。

**Bug 2：模組層級的快取沒有失效機制，「記帳前後」拿到同一份結果**

快取的 key 只有 `month`，沒有考慮 `data` 變了。`recordText_`（`src/Main.js`）的流程是：

1. `const before = monthSummary(cur, data);` → 計算並**存進快取**
2. 寫入新的交易，`data.txs = data.txs.concat(written)`
3. `budgetStatus_` 裡 `const after = monthSummary(cur, data);` → **直接回傳快取，也就是 before 那份**

結果：

- `crossedThreshold(before.pct, after.pct, …)` 的兩個值永遠一樣，**50／30／10% 門檻提醒永遠不會觸發**；
- 記帳回覆卡片上的「剩餘」和進度條，顯示的是**記這筆之前**的數字；
- 補記舊月份後，「已自動重新結算」的訊息也是假的。

在 Apps Script 裡，全域變數在同一次執行（一次 `doPost`）裡會一直存在，所以這個 bug 在正式環境一定會發生；在 Node 測試裡，如果模組只載入一次，快取還可能跨測試案例存活，讓測試結果互相影響。

修法：拿掉快取；真的需要效能，就讓 `pendingSurplus` 自己跑一次迴圈（像這版那樣用 `summariesUntil` 算一次），但不要把結果存在模組層級。以這個專案的資料量（一個人、幾年份的月份），O(n²) 根本不是瓶頸，這次「優化」本身就不必要。

**怎麼防**：

- 看到 AI 加了「快取」，第一個問題永遠是：**key 包含了所有會影響結果的輸入嗎？什麼時候失效？**
- 請 AI 做效能優化前，先要求它說明瓶頸在哪裡、量測數字是多少。沒有數字的優化，通常只是在增加 bug 的機會。
- 補一個 `gas-sim` 測試：記一筆讓剩餘從 55% 掉到 45% 的帳，斷言回覆裡有「只剩不到 50%」。

</details>
