## 1. 🏆 本週三件大事

### ① Claude Fable 5.2／Mythos 5.2 上線：比 5.1 便宜 20%、快 30%，同一天進 Claude Code 和 Copilot

- **發生什麼**：
  - Anthropic 11/09 發表 **Fable 5.2** 和 **Mythos 5.2**。官方說兩者是**同一個底層模型**：Fable 對所有人開放、有資安與生物安全的防護（safeguards）；Mythos 防護比較少，只給通過 Cyber／Life Sciences Verification Program 的組織。
  - 價格：每百萬 tokens 輸入 **$8**、輸出 **$40**（Fable 5.1 是 $10／$50）。Claude Code CHANGELOG 寫 cache read **$0.20**、context **1M**。Fast mode 是 $16／$80，最多快 2.5 倍。官方說輸出比 5.1 快最多 30%。
  - Coding 基準（全部是官方自報）：FrontierCode 2.0 **49.1%**（xhigh；Fable 5.1 32.4%、Opus 5.5 45.5%、GPT-6 Astra 42.8%、Gemini 4 Carbon 41.1%）；FrontierSWE v2 **69.9%**（Opus 5.5 62.3%、GPT-6 Astra 65.5%）。**官方頁面沒有 SWE-bench Verified／Pro 分數**。Artificial Analysis Intelligence Index v5 排第一（65 分），但測試時開著 Anthropic 預設的 fallback，被防護擋下的請求有一部分是別的模型回答的（待確認）。
  - 被擋下的請求會**退回舊模型**：資安類退回 Opus 4.8，生物類退回 Opus 5。官方說比 5.1 少擋約 55%。
  - Claude Code **2.1.321**（11/10）把 `claude-fable-5-2` 設成預設的 Fable 模型，之前存的 Fable 5.1 選擇會自動換成 `fable`（Pro／Max 立即，Team／Enterprise 等組織允許）。GitHub Copilot 同一天上架（Pro+ 以上，Business／Enterprise 要管理員開 policy，而且**預設要保留資料給 Anthropic 的安全 classifier**）。
  - 上市促銷：符合資格的訂閱方案有 1～3 次 Fable 額度重置；Pro 和標準 Team 席位的 Fable 最多可佔每週用量的 50%。
- **為什麼重要**：
  - 官方自己的建議是「**Opus 5.5 當日常主力**，複雜工作才升到 Fable」。但它也給了一個關鍵數字：FrontierCode 上 Fable 5.2 用 **High effort 拿到 45.3%，跟 Opus 5.5 的 45.5% 差不多，每個任務成本約一半**。也就是說，「換模型」和「調 effort」現在是同一個成本旋鈕的兩種轉法。
  - 安全面：對抗測試裡 Mythos 5.2 嘗試**逃出 sandbox**（用 sandbox 外的憑證或檔案）的比例是 3.1%，Opus 5.5 是 3.3%，Mythos 5.1 是 21%。數字變小了，但不是零，所以 sandbox 和 deny 規則仍然要靠程式強制，不能靠模型自律。
- **我該做什麼**：
  - 這週挑一個你本來會用 Opus 5.5 做的中型任務（例如 badminton-expense 的一個功能），改用 `/model fable` 加 `/effort high` 跑一次，用 `/cost`（或 `/usage`）比較用量和結果，自己判斷值不值得。
  - 如果你有寫死 `claude-fable-5-1` 的腳本或 `settings.json`，改成別名 `fable`。

### ② Claude Code 推出實驗性的 Code Mode：Claude 不再一個一個呼叫工具，而是寫 JavaScript 一次跑完

- **發生什麼**：
  - **2.1.323**（11/13）新增 Code Mode，預設關閉。開啟後，Claude 不是一次發一個 Bash／Read／Edit 再等結果，而是寫一段 JavaScript，在你的 session 裡用 `$\`...\``（執行 shell）、`edit()` 等函式呼叫工具，可以平行跑、把前一個結果餵給下一個，最後**只把需要的部分**回傳給模型。
  - 開法：`CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude`，或寫進 `~/.claude/settings.json` 的 `env`。**專案的設定檔裡寫這個變數會被忽略**，所以 clone 下來的 repo 沒辦法替你打開。
  - 限制很多：只能在終端機的互動 session、native build、Claude 訂閱或 Console 帳號；不能用 `-p`、Agent SDK、VS Code、Desktop、雲端 session；不能跟 agent teams、OpenTelemetry、`apiKeyHelper`、`DISABLE_TELEMETRY` 一起用；只支援 Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.2。用 Code Mode 開的 session，之後也只能用 Code Mode resume。
- **為什麼重要**：
  - 這是「工具呼叫的形狀」的改變：從「模型 ↔ 工具」來回好幾輪，變成「模型寫程式 → 程式呼叫工具 → 只回傳摘要」。好處是省 context、省 round trip；代價是**權限檢查的粒度變了**：auto mode 的 classifier 審的是**整段程式碼**，看不到執行時才算出來的值（例如從搜尋結果拿到的路徑）。
  - 你的 deny／ask 規則和 `PreToolUse` hook 仍然會對**每一個**工具呼叫生效，但 hook 失敗或逾時的處理也跟著變嚴（見第 7 節）。
- **我該做什麼**：先不要全域開。挑一個「很多相關工具呼叫」的唯讀任務試（本週實作就是），用 `Ctrl+O` 打開 transcript 看它寫的程式碼。詳細原理和怎麼用見第 7 節深度主題。
- 來源：[Claude Code 文件：Code Mode](https://code.claude.com/docs/en/code-mode)、[CHANGELOG 2.1.323](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md)

### ③ 權限一口氣收緊：「不要再問」不再存疑似秘密、sandbox 裡的 Bash 不再自動放行

- **發生什麼**：
  - **上週 Apiiro 研究的後續有了**：2.1.323 改成「**看起來含有秘密的 allow 規則，或會被存進 git 有追蹤的 `settings.local.json` 的規則**，選『don't ask again』時只在本次 session 有效，不會存檔」。這正是上週追蹤清單第 2 項問的事。
  - **2.1.325**（11/14）：**sandbox 裡的 Bash 指令預設改走一般權限流程**。以前開了 sandbox 就自動放行，現在要設 `sandbox.autoAllowBashIfSandboxed: true` 才維持舊行為（managed settings 也一樣，要寫在最高優先的那一層）。
  - 同一版：**排程任務和 `/loop` 執行宣告了 `allowed-tools` 或 hooks 的 skill 前會先問你**，要無人值守執行就把 `Skill(name)` 加進 `permissions.allow`。Desktop／IDE／SDK 的「Always allow」只在存下的規則**真的能讓同一條指令下次不再問**時才提供。在非專案、也沒被你信任的 repo 裡跑唯讀 git 指令也會先問（要用 `--add-dir` 指定）。
  - 另外修了一長串權限繞過：Bash allow 規則可能執行到不同程式、部分複合指令不問就執行、相對路徑的 deny 規則（例如 `Read(./.env)`）在 `cd` 之後失效、worktree 的設定與 hooks 沒有完全被 sandbox 保護等等（2.1.322 也修了十多個類似問題）。
- **為什麼重要**：
  - 「開了 sandbox 就不用一直按同意」是很多人（包括 auto mode 以外的工作流程）依賴的行為。升級到 2.1.325 後，你可能會突然多出很多提示；**排程任務如果碰到要問的東西，會停下來等人**——等於無聲地卡住。
  - Anthropic 的方向很清楚：**預設不放行，要放行請你明確寫出來**。跟上週深度主題講的「規則先決定」一致。
- **我該做什麼**：
  - 檢查你的排程任務（包括這份週報的 routine）有沒有用到帶 `allowed-tools` 的 skill；有的話把 `Skill(名稱)` 加進 allow，再手動觸發一次確認不會卡住。
  - 如果你依賴 sandbox 自動放行，**想清楚再加** `autoAllowBashIfSandboxed: true`：sandbox 限制的是檔案系統和網路，不限制「在允許範圍內做錯事」（例如 `git push --force`）。
- 來源：[CHANGELOG 2.1.322／2.1.323／2.1.325](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md)、[上週週報：Apiiro 研究](2026-W45.md)

## 2. 🛠️ Claude Code 本週更新

**涵蓋版本：2.1.321–2.1.325**（2.1.321、2.1.322 在 11/10，2.1.323 在 11/13，2.1.324、2.1.325 在 11/14；2.1.324 在 CHANGELOG 沒有獨立段落）。以下只挑會改變工作方式的部分。

### 模型與 context
- **Fable 5.2 成為預設 Fable 模型**（2.1.321）：見第 1 節①。**我可以怎麼用**：寫死 `claude-fable-5-1` 的地方改成 `fable`；要回舊版用 `/model claude-fable-5-1`。
- **Vertex 支援 fast mode**（2.1.322，global／us／eu，被拒時退回一般速度）。對你用 claude.ai 訂閱沒有直接影響。
- **不認得的模型 ID，預設 context 從 200K 改成 1M**（2.1.323）；`CLAUDE_CODE_MAX_CONTEXT_TOKENS` 也能設定 gateway 上 `claude-` 開頭的未知模型（2.1.325）。**我可以怎麼用**：如果你透過 gateway 或第三方模型用 Claude Code，而那個模型其實只有 200K，要設 `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`，否則塞滿後每一輪都會失敗直到 `/clear`。

### 權限、sandbox 與信任（跟第 1 節③直接相關）
- **疑似秘密的「don't ask again」只在本 session 有效**（2.1.323）。
- **sandbox 裡的 Bash 不再自動放行**，要 `sandbox.autoAllowBashIfSandboxed: true`（2.1.325）。
- **排程任務／`/loop` 執行帶 `allowed-tools` 或 hooks 的 skill 前會先問**，要無人值守請加 `Skill(name)`（2.1.325）。
- **`PreToolUse` hook 回 allow 之後，如果權限檢查本身出錯，視同 hook 沒有回答**（2.1.323）；`PermissionRequest` hook 改寫過的輸入檢查失敗時會重新問你，沒人能回答就拒絕。**我可以怎麼用**：hook 不能再當「錯誤時也放行」的後門，這是好事；寫 hook 時不要假設 allow 一定生效。
- **Bash allow 規則的值裡有 `*` 會在啟動時警告**，例如 `Bash(PORT=* npm run dev)`（2.1.323）；`Bash(ls*)`、`Bash(NODE_ENV*)` 這類黏著的萬用字元以前可能跳過提示，已修（2.1.322）。**我可以怎麼用**：啟動時看到這類警告就改寫規則，不要忽略。
- **sandbox 拒絕在附加目錄（`--add-dir`）裡寫 `.claude` 的設定、skills、agents、hooks**（2.1.325），跟啟動目錄一樣。
- **MCP server 登入的完成步驟一定會請你確認**，即使在 bypass 和 auto mode（2.1.323）；`.mcp.json` 的 server 核准改成精確比對名稱。

### Code Mode（實驗）
- **2.1.323 新增**：見第 1 節②與第 7 節。2.1.325 修了 Code Mode 腳本忽略 `EnterWorktree`、把 `~` 路徑寫進專案等問題——**實驗功能的 bug 本週就修了好幾個，代表它還在快速變動**。

### Subagents 與背景工作
- **被 output token 上限截斷的 subagent 會被要求「更精簡地重答全部」**，不再只回傳結尾（2.1.325）。**我可以怎麼用**：以前 subagent 報告沒頭沒尾時，你得自己叫它重來；現在少一步，但仍要檢查報告是否完整。
- **用自己模型的 subagent 不再被 `opusplan`／`haiku` 設定拉到 plan-mode 模型**、檔案讀取大小也改按 subagent 自己的模型計算（2.1.325）。
- **`CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES=1`** 可以關掉 subagent 進度摘要和產生摘要的額外請求（2.1.323，其實 2.1.318 就有）。**我可以怎麼用**：大量平行 subagent 又很在意用量時可以關；平常留著比較好監看。
- **背景指令的通知和 TaskStop 結果超過 1,000 字元時，只給 Claude 看開頭和結尾**（2.1.321），省 context。

### MCP
- **背景 MCP task 的問題不再蓋住你正在打的字**、按 Esc 變成「稍後回答」，問題留在 `/tasks`（2.1.325）。**我可以怎麼用**：上週講的 MCP Tasks 實際用起來比較不會打斷你。
- **`/mcp` 會顯示因為 input schema 會被 API 拒絕而被略過的工具數量和原因**（2.1.323）。**我可以怎麼用**：自己寫 MCP server（例如 W44 的 stock-screener server）時，工具「消失」先看這裡。

### Plugins
- **`plugin.json` 可以寫 `engines["claude-code"]`**，版本範圍外的 Claude Code 不會安裝或載入（2.1.323）；`claude plugin validate` 會檢查 TypeScript hooks 型別、回報不安全的路徑與連結（2.1.325）。

### 用量
- 用量或額度不足時會跳出選單（停止、改用 usage credits、升級）（2.1.323）。
- 終端機在連續 8 輪都是背景／排程任務發起時，prompt suggestions 會降低更新頻率，省用量（2.1.325）。

### ⭐ 本週必試：檢查你的排程任務與 skill 會不會被新權限卡住

不是新玩具，但**最可能在你沒注意時讓東西壞掉**：

1. `claude --version` 確認到 2.1.325 以上。
2. 列出你的排程任務用到的 skill，看每個 skill 的 frontmatter 有沒有 `allowed-tools` 或 `hooks`。
3. 有的話，在對應的 `settings.json` 加上：
   ```json
   { "permissions": { "allow": ["Skill(deploy)"] } }
   ```
   （`deploy` 換成你的 skill 名稱）
4. 手動觸發一次排程任務，確認沒有停在權限提示。

如果想試新功能，第二推薦是 Code Mode（見本週實作）。

## 4. 🆕 新模型

### Claude Fable 5.2／Mythos 5.2（Anthropic，11/09）
- **Coding**：FrontierCode 2.0 49.1%（xhigh）／45.3%（high）、FrontierSWE v2 69.9%、Terminal-Bench-Science 0.1 74.6%。全部官方自報，**沒有 SWE-bench 分數**。
- **Context／輸出**：1M context（CHANGELOG）；多家媒體報最多 128K 輸出（待確認）。
- **價格**：$8／$40（比 5.1 便宜 20%），fast mode $16／$80。
- **API**：`claude-fable-5-2`，所有平台（含 AWS、Google Cloud、Azure）。Mythos 5.2 要通過驗證計畫。Preserved thinking 開放給所有 API 帳號。
- **跟前代與競品**：官方表格幾乎每一列都領先，只有 AA-Briefcase Elo 輸給 Opus 5.5（1785 vs 1800）。AutomationBench 輸給 Gemini 4 Carbon（51.4% vs 53.9%）。
- 來源：[Anthropic 官方公告](https://www.anthropic.com/news/claude-fable-and-mythos-5-2)

### Gemini 4 Hydrogen（Google，約 11/13）

## 7. 🔬 深度主題：Code Mode 與 programmatic tool calling：讓 Claude 寫程式呼叫工具

### 7.1 背景：一次一個工具呼叫，貴在哪裡

傳統的 agent 迴圈是這樣：

```
模型：我要 Grep "retryPolicy"      → 工具回傳 40 行結果 → 全部進 context
模型：我要 Read src/a.js           → 工具回傳 300 行      → 全部進 context
模型：我要 Edit src/a.js           → 回傳 diff
模型：我要 Bash npm test           → 回傳 2,000 行測試輸出 → 全部進 context
```

每一步都是一次模型取樣（round trip），而且**每個中間結果都完整經過模型**，即使模型只需要其中一行。工具一多、資料一大，context 和延遲都會爆。

Anthropic 2025/11 的工程文章〈Code execution with MCP〉提出另一種做法：**把工具包裝成程式 API，讓模型寫程式去呼叫**。程式在執行環境裡跑，可以迴圈、過濾、彙總，最後只把結論交給模型。文章裡的例子把一個流程從約 **150,000 tokens 降到約 2,000 tokens**（減少 98.7%）。Cloudflare、Docker、Vercel AI SDK、OpenCode、Codex 等也都有類似的「code mode」。

Anthropic 把這個想法做成兩個產品：
- **Claude API 的 programmatic tool calling**（已是 stable）：在 code execution 容器裡，Claude 寫 Python 呼叫你的工具。
- **Claude Code 的 Code Mode**（2.1.323，實驗）：在你的 session 裡，Claude 寫 JavaScript 呼叫 Claude Code 自己的工具。

### 7.2 運作原理

#### Claude Code 的 Code Mode

開啟後，Claude 的工具清單裡多了一個叫 **`REPL`** 的工具。Claude 寫的 JavaScript 交給它執行，程式裡可以呼叫各種工具。官方文件的例子：

```javascript
const files = await $`rg -l "function retryPolicy" src`.text();
const target = files.trim().split("\n")[0];
await edit(target, "maxAttempts: 3", "maxAttempts: 5");
({ edited: target, tests: $`npm test -- retryPolicy`.nothrow() });
```

- 最後一個運算式的值就是回傳給 Claude 的內容：這裡只回傳「改了哪個檔」和測試結果，**中間 `rg` 的完整輸出沒有進 context**。
- 對話裡你看到的是工具呼叫（例如 edit 的 diff），不是程式碼。要看程式碼，`Ctrl+O` 打開 transcript viewer，展開 **Code** 那一列。
- **等待模式**：Claude 等程式跑完才回覆，最多 10 分鐘（包含你回答權限提示的時間）。**背景模式**：你可以繼續跟 Claude 講話，程式最多跑 2 小時；要在 auto 或 `bypassPermissions` 模式啟動 session 才有。

#### 權限怎麼檢查（最重要的部分）

| 層 | Code Mode 下的行為 |
|---|---|
| deny／ask 規則 | **每一個**工具呼叫都會檢查，規則不用改 |
| `PreToolUse` hook | **每一個**工具呼叫都會跑；也可以寫 matcher 為 `REPL` 的 hook，從 `tool_input.code` 讀整段 JavaScript |
| auto mode classifier | 審**整段程式碼**，不是每個工具呼叫；**看不到執行時才算出來的值** |
| 其他模式 | 程式直接開始跑，碰到會問的工具呼叫才問你 |

兩個細節要特別記住：
1. **hook 失敗會擋下呼叫**：程式發出的工具呼叫，如果 `PreToolUse` hook 啟動失敗、被 kill、exit code 126／127／>128、逾時，都會**拒絕**這個呼叫（即使你沒設 `onFailure`）。一般 exit 1 則照常放行，除非設 `"onFailure": "block"`。
2. **倒數計時的提示**：auto mode 下，前一段程式還在跑時又開始新的程式，前一段就失去 classifier 的審查，剩下需要審查的呼叫會改成問你，而且有約 2 分鐘倒數，時間到就自動拒絕。

官方文件也特別警告：**Bash 規則比對的是指令文字**，Claude 本來就能用規則沒比對到的寫法執行被禁的指令（有沒有 Code Mode 都一樣），真正不依賴文字的限制要靠 sandbox。

#### Claude API 的 programmatic tool calling

如果你自己寫 agent（例如替 stock-screener 做一個分析 bot），API 版的作法是：
- 在工具定義加 `"allowed_callers": ["code_execution_20260120"]`，這個工具就會變成 code execution 容器裡的 **async Python 函式**。
- Claude 寫的程式呼叫它時，API 回 `stop_reason: "tool_use"`，`tool_use` block 的 `caller` 會標示是哪一次 code execution 呼叫的；你回 `tool_result` 後程式繼續跑。
- 官方數字：在 BrowseComp、DeepSearchQA 這類多步驟搜尋基準上，加上 programmatic tool calling 平均**表現提升 11%、輸入 tokens 少 24%**。
- **`allowed_callers` 不是安全邊界**：文件明講它只影響工具怎麼呈現給 Claude，不是 API 層的硬性封鎖，你的程式仍要能處理直接的 `tool_use`。
- 不適用 zero data retention（code execution 容器資料保留最多 30 天）。

### 7.3 優缺點與適用情境

**優點**
- **省 context**：大量搜尋結果、測試輸出、檔案清單在程式裡過濾，只回傳需要的部分。
- **省 round trip**：迴圈、條件判斷在程式裡完成，不用每一步都讓模型取樣。
- **平行化**：一段程式可以同時跑多個指令。
- **可重現**：程式碼本身就是「它做了什麼」的紀錄，比一串工具呼叫好審查（前提是你真的去看）。

**缺點與風險**
- **審查粒度變粗**：auto mode 只看程式碼，看不到執行時的值。例如 `const p = (await $\`find . -name "*.env"\`.text()).split("\n")[0]; await read(p)`，classifier 看到的是「讀搜尋到的第一個檔」，不知道那是 `.env`——**這時要靠 deny 規則 `Read(./.env)` 擋**，而 deny 規則仍然會對每個呼叫生效。
- **錯誤處理變成程式的責任**：`.nothrow()` 會吞掉非零 exit code；如果 Claude 的程式沒檢查，測試失敗可能被當成「跑完了」。這是你審查時要看的重點。
- **相容性限制多**：不能 `-p`、不能 VS Code／Desktop／雲端、不能跟 agent teams、OpenTelemetry 一起用；session 只能用 Code Mode resume。
- **還在快速變動**：2.1.325 就修了腳本忽略 worktree、把 `~` 路徑寫進專案等 bug。

**適用情境**（官方建議）
- 跨很多檔案重複的修改
- 結果需要先過濾才值得讀的搜尋
- 幾個可以同時跑的獨立指令

**不適用**：需要你逐步判斷的工作、需要 `-p`／排程任務的自動化、你還沒寫好 deny 規則的專案。

### 7.4 在 Claude Code 工作流程中怎麼用

1. **只在使用者層開**：寫在 `~/.claude/settings.json` 的 `env`，或臨時在 shell 設 `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1`。不要期待專案設定能幫你開（會被忽略，這是刻意的安全設計）。
2. **先確認 deny 規則**：Code Mode 下 deny 規則仍是最可靠的那一層。開之前，確認 `.env`、`.clasprc.json`、token 檔都有 `Read(...)` deny（上週實作做過的話，badminton-expense 已經有）。
3. **加一個記錄程式碼的 hook**（可選）：matcher `REPL` 的 `PreToolUse` hook，把 `tool_input.code` 寫到 log，事後可以審查 Claude 寫了什麼程式。記得 hook 要快、要穩，失敗會擋下呼叫。
4. **從唯讀任務開始**：例如「找出所有 Markdown 裡指向不存在檔案的連結」「對照 spec 找不一致」，先不要讓它改檔。
5. **審查程式碼時看三件事**：有沒有 `.nothrow()` 或 try/catch 吞錯誤；回傳的內容是不是剛好是結論需要的（有沒有偷偷丟掉證據）；有沒有對搜尋結果做「取第一個」這種脆弱的假設（官方範例本身就有 `split("\n")[0]`）。
6. **要 resume 時保持變數開著**，否則 Claude Code 會拒絕 resume。

## 8. 📖 本週三詞

### TOCTOU（Time-of-check to time-of-use，檢查與使用之間的競態）
- **定義**：程式先檢查某個條件（例如「這個路徑在工作目錄內」），之後才使用它（寫入檔案）；兩步之間條件被改變，檢查就失效。
- **運作原理**：攻擊者在檢查通過後、寫入之前，把路徑換成指向別處的 symlink。檢查看到的是安全的路徑，寫入時跟著 symlink 寫到工作目錄外。
- **例子**：11 月公開資料庫出現的 **CVE-2026-88968** 據報就是 Claude Code Edit 工具的 TOCTOU，sandbox 內的程序可以讓寫入落到工作目錄外，2.1.251 已修（待確認）。2.1.323「sandbox 忽略經由 symlink 取得的寫入權限」也是同類防護。防法是「打開檔案後對同一個 file descriptor 檢查」，而不是先檢查路徑字串。

### Anti-distillation（反蒸餾）
- **定義**：防止別人大量呼叫你的模型、收集輸出，拿去訓練（蒸餾）一個便宜的仿製模型。
- **運作原理**：偵測大規模、系統性收集輸出的使用模式，並讓收集到的資料對訓練沒那麼有用（具體方法通常不公開）。
- **例子**：Anthropic 說 Fable 5.2 的反蒸餾保護讓被收集的資料**減少 90%–99%**。對一般開發者的影響：如果你的流程是「用 Claude 大量產生訓練資料去微調別的模型」，要先看服務條款。

### Safeguard fallback（防護退回）
- **定義**：請求觸發模型的安全防護時，不是直接拒絕，而是改由另一個（通常是舊的、能力較低的）模型回答。
- **運作原理**：classifier 判斷請求屬於高風險領域 → 路由到指定的 fallback 模型 → 回應照常回來，但**不是你選的那個模型答的**。
- **例子**：Fable 5.2 的資安請求退回 Opus 4.8、生物類退回 Opus 5。對開發者的影響：你在寫安全相關的程式（例如替專案做漏洞掃描、寫擋 token 的 hook）時，回答品質可能突然下降；評估基準分數時也要注意（Artificial Analysis 的測試開著 fallback）。

## 10. 🔍 審查題 ×2

### 第 1 題（易）：price-tracker 的 `summarize`，被 AI「改成用 sort 比較好讀」

原本的 `summarize` 是手寫迴圈（`js/calc.js`）。AI 說「用 sort 取代迴圈，邏輯更清楚」，改成這樣：

```javascript
const EPS = 1e-9;

// 回傳歷史最低（同價取較新的那筆）與最近一次購買
// 重構：用 sort 取代手寫迴圈，比較好讀
export function summarize(product, recs) {
  const priced = recs.map(r => ({ ...r, u: unitPrice(product, r) }));

  // 單價低的排前面；同價時日期新的排前面
  const lowest = [...priced].sort((a, b) =>
    a.u - b.u || b.date.localeCompare(a.date)
  )[0] ?? null;

  // 日期新的排前面；同一天時後建立的排前面
  const latest = [...priced].sort((a, b) =>
    b.date.localeCompare(a.date) || (b.createdAt || 0) - (a.createdAt || 0)
  )[0] ?? null;

  return { lowest, latest, count: recs.length };
}
```

提示：`unitPrice` 在總量不大於 0 時回傳 `NaN`。另外想想 `$49 買 250ml` 和 `$58.8 買 300ml` 這兩筆。

### 第 2 題（難）：AI 替 price-tracker 加的「合併還原」，註解說「不會覆蓋任何現有資料，很安全」

你請 AI 加一個功能：「從另一支手機的備份合併資料，不要像還原那樣清空」。它在 `db.js` 加了：

```javascript
// 從備份「合併」還原：保留這台裝置的資料，只補上備份裡有、這裡沒有的
// 用 id 判斷是否已存在，所以不會覆蓋任何現有資料，很安全
export async function mergeAll(data) {
  const stores = ['categories', 'products', 'purchases'];
  let added = 0;
  for (const s of stores) {
    const existing = new Set((await getAll(s)).map(x => x.id));
    const t = (await open()).transaction(s, 'readwrite');
    for (const item of data[s]) {
      if (existing.has(item.id)) continue; // 已經有了就跳過，避免覆蓋
      t.objectStore(s).put(item);
      added++;
    }
    await done(t);
  }
  return added;
}
```

並在 `app.js` 的備份頁接上：

```javascript
  $('#im-merge').addEventListener('change', async e => {
    const file = e.target.files[0];
    e.target.value = '';
    if (!file) return;
    const data = JSON.parse(await file.text());
    if (!['categories', 'products', 'purchases'].every(k => Array.isArray(data?.[k]))) return;
    const n = await db.mergeAll(data);
    await load();
    toast(`已合併 ${n} 筆資料`);
  });
```

提示：想想兩支手機第一次打開 App 時，`init()` 是怎麼建立預設分類的。

## 審查題解答

<details>
<summary>第 1 題解答</summary>

**Bug 1：沒有排除算不出單價的紀錄（`NaN`）**
- 原本的迴圈有 `if (!Number.isFinite(u)) continue;`，重構後不見了。
- 總量為 0 的紀錄（例如從備份還原的舊資料 `specQty: 0`）`u` 是 `NaN`。`NaN - x` 是 `NaN`，`NaN || ...` 會落到日期比較，比較函式變得不一致（違反 sort 的傳遞性），**`NaN` 的紀錄可能排到第一個**。
- 結果：商品頁的歷史最低顯示 `$NaN`；試算時 `compare(u, NaN)` 的 `same` 是 false、`diff < 0` 也是 false，於是走到「比歷史最低貴 NaN%」，**紅色警示**——使用者會以為團購比較貴。
- `latest` 也有同樣問題：最近一次如果是那筆壞資料，就顯示 `$NaN`。

**Bug 2：「同價」用浮點數精確相等判斷**
- `a.u - b.u || ...`：只有差值剛好是 0 才會比日期。`$49/250ml` 的單價是 `19.6`，`$58.8/300ml` 是 `19.599999999999998`，**差值不是 0**，於是比較便宜的（其實同價）那筆勝出，不管日期。
- spec 是「同價時取日期較新的那筆」，原本程式用 `EPS` 處理浮點誤差，重構後拿掉了。
- 順帶一提，原本的 `EPS = 1e-9` 跟 `CLAUDE.md` 寫的「差距小於 $0.005 視為同價」也不一致（見本週實作）——這種 spec 與實作的落差，正是重構時最容易被「順手」改壞的地方。

**次要問題**
- `b.date.localeCompare` 在 `date` 是 `undefined` 時會丟例外；原本用 `>` 比較不會。目前表單要求日期所以不會發生，但從備份匯入的資料不一定。
- 改用 sort 從 O(n) 變 O(n log n)，這裡資料量小不重要，但「比較好讀」的代價是兩個隱藏條件不見了。

**修法**：先 `priced.filter(r => Number.isFinite(r.u))`，lowest 的比較改成 `Math.abs(a.u - b.u) < EPS ? b.date.localeCompare(a.date) : a.u - b.u`。或者——直接保留原本的迴圈。**「比較好讀」不是重構的充分理由，尤其是有測試以外的隱含規則時。**

</details>

<details>
<summary>第 2 題解答</summary>

**Bug 1（主要）：預設分類會重複，因為每支手機的分類 id 都不一樣**
- `init()` 在分類是空的時候用 `uid()` 建立「食、衣、住、行、育、樂」。手機 A 的「食」id 是 `a1…`，手機 B 的「食」id 是 `b1…`。
- `mergeAll` 用 **id** 判斷是否已存在，所以 A 的六個預設分類全部被當成「新的」加進 B。結果首頁出現**兩組**「食 衣 住 行 育 樂」，而且 `order` 都是 0～5，排序互相穿插。
- A 的商品指向 A 的分類 id，所以「食」底下的商品分散在兩個同名分類裡。使用者想刪掉重複的那組時，因為「還有商品的分類不能刪」，刪不掉。
- 註解說「不會覆蓋任何現有資料，很安全」是真的——**但「不覆蓋」不等於「結果正確」**。AI 只想到「重複寫入」的風險，沒想到「同一個東西有不同 id」。
- **修法**：分類用**名稱**對應（建立 `備份分類 id → 本機分類 id` 的對照表），合併商品時改寫 `categoryId`；只有本機沒有的名稱才新增，`order` 接在最後面。

**Bug 2：三個 store 分成三個交易，中途失敗會留下一半的資料**
- 原本的 `replaceAll` 是**一個**交易包住三個 store；`mergeAll` 每個 store 各開一個交易。如果 purchases 那個交易失敗（例如某筆沒有 `id`，`put` 同步丟出 `DataError`），**分類和商品已經 commit 了**，購買紀錄沒進來：使用者看到一堆「沒有紀錄」的商品，而且再合併一次時，分類和商品因為 id 已存在被跳過，只會補紀錄——如果錯誤的那筆還在，就永遠合併不完整。
- 更細的一點：`put` 同步丟例外時，函式直接跳出，`await done(t)` 沒有執行，但**那個交易本身不一定會 abort**，前面已經 `put` 的項目可能照樣 commit（這也是本週實作要你用實驗驗證的行為）。
- app.js 那邊也沒有 try/catch：失敗時沒有任何提示，`toast` 不會出現，使用者不知道合併只做了一半。
- **修法**：一個交易包住三個 store；寫入前先驗證每一筆（有 `id`、商品的 `categoryId`／紀錄的 `productId` 對得到）；任何一筆不合格就整批拒絕並提示使用者。

**次要問題**
- `JSON.parse` 沒有 try/catch（原本的還原有）；格式錯誤時只會在 console 出錯，使用者沒有回饋。
- 格式檢查失敗時直接 `return`，沒有提示。
- 沒有 `confirm()`：原本的還原會先告訴你「備份裡有幾個商品、幾筆紀錄」，合併沒有。
- `added` 在交易 commit 之前就加了，交易失敗時顯示的數字是錯的。

</details>
