## 1. 🏆 本週三件大事

### ① 「Yes, and don't ask again」把密碼和 token 寫進 `settings.local.json`，上千份被推到公開 GitHub

- **發生什麼**：
  - 資安公司 Apiiro 11/05 發表研究：在 Claude Code 權限提示選「Yes, and don't ask again」，會把**整條指令**存成 `allow` 規則寫進 `.claude/settings.local.json`。如果那條指令裡有 `curl -H "Authorization: Bearer xxx"`、`PGPASSWORD=... psql`、`export API_KEY=...`，秘密就原封不動地留在檔案裡。
  - Apiiro 在公開 GitHub 找到 **104,185 份** `.claude/settings.local.json`（分布在 103,617 個 repo），其中 **1,122 份（約 1.1%）含秘密**。把 git 歷史、共用的 `settings.json` 和 agent transcript 一起算，總共 **2,539 個不同的秘密、1,994 個 repo**。Apiiro 沒有測試這些秘密是否仍有效，媒體也沒有獨立驗證數字；Apiiro 本身賣資安產品。截至 11/08 沒找到 Anthropic 的正式回應。
  - 官方文件的說法（我直接讀了 [settings 文件](https://code.claude.com/docs/en/settings)）：Claude Code **第一次寫這個檔案時**，會把 `**/.claude/settings.local.json` 加進你的**全域 git excludes**（`core.excludesFile`，沒設就是 `~/.config/git/ignore`）。但**如果檔案是你手動建立的、還沒被 Claude Code 寫過，就要自己加 `.gitignore`**。所以外洩的路徑大概是：手動建立、舊版行為、換一台沒有那個 excludes 的電腦後 `git add -A`，或 `git add -f`（推論，待確認）。
  - 來源：[The Hacker News](https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html)（待確認，網站連不上）、[iTWire](https://itwire.com/business-it-news/security/claude-code-approval-files-found-exposing-company-secrets-on-github-says-apirro-researchers)、[Let's Data Science](https://letsdatascience.com/news/apiiro-finds-claude-code-approvals-leaking-2539-secrets-on-g-e4f20dbc)、[DEV Community 整理](https://dev.to/paullovelace/claude-codes-dont-ask-again-leaked-developers-secrets-to-public-github-explained-honestly-4dck)、官方 [Configure permissions](https://code.claude.com/docs/en/permissions)
- **為什麼重要**：
  - W42 談「`.claude/` 被當攻擊面寫進 repo」，W44 談「工具的安裝通路被冒用」，這週是**你自己按下的『同意』變成外洩**。這不是漏洞，是設計：權限規則就是指令字串，指令裡有什麼它就存什麼。
  - 我查了你的五個專案：**只有 price-tracker 的 `.gitignore` 明確排除 `.claude/settings.local.json`**；expense-tracker、badminton-expense、stock-screener、loan-tracker 都沒有，完全靠全域 excludes。badminton-expense 由 Claude 直接 `npm run deploy`，LINE token 在 Script Properties，**只要曾經讓 Claude 用 curl 測 LINE API，token 就可能在那個檔案裡**。
- **我該做什麼**：
  1. 每個 repo 跑一次 `git check-ignore -v .claude/settings.local.json`，沒有輸出就代表**沒被忽略**；再跑 `git log --all --oneline -- '**/.claude/settings.local.json'` 確認歷史裡沒有。
  2. 打開 `~/` 底下所有 `settings.local.json` 搜一次 `Bearer`、`TOKEN`、`PASSWORD`、`KEY=`，有就**先輪換憑證**，再刪規則。
  3. 改習慣：**含秘密的指令只按「Yes」（單次），不要按「don't ask again」**；秘密一律走環境變數或 Script Properties。本週實作會把這件事變成 hook。

### ③ Claude Code 2.1.317–2.1.319：卡住的權限提示可以直接變成拒絕，MCP 長任務自動進背景

- **發生什麼**：
  - **`permissions.denyInsteadOfPrompting`**（2.1.319）：本來會停下來等你按權限提示的工具呼叫，改成**直接拒絕、回合繼續**，適用於終端機 session、subagents、teammates。
  - **MCP tasks**（2.1.319）：MCP server 把一個 tool call 當成 task 執行時，Claude Code 立刻把它移到背景，完成後通知 Claude；要等它可以設 `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND`。
  - 一批權限繞過修正：**精心構造的環境變數前綴可以把部分指令藏起來不被權限檢查**、`sed` 在 accept-edits／auto mode 可能跳過檢查、**建立 worktree 時的 sandbox escape**、含引號的字詞讓 Bash deny／ask 規則漏掉（全部 2.1.319）。
  - `claude -p` 在更多失敗情境改成 exit 1（auto mode 因沒有安全檢查而拒絕、磁碟滿導致 transcript 寫不進去）；stored login 到期前 10 天開始在 stderr 警告（2.1.317–2.1.318）。
  - 來源：[CHANGELOG](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md)、[npm registry 發布時間](https://registry.npmjs.org/@anthropic-ai/claude-code)
- **為什麼重要**：
  - 之前讓 Claude 無人看管地跑（`claude -p`、排程、背景 subagent），碰到要權限的動作就是**卡住**或**整個失敗**。`denyInsteadOfPrompting` 讓「沒預先允許的事就不做、但其他事繼續做」成為可設定的行為，這是 headless 工作流程的關鍵拼圖。
  - Bash 權限規則是「比對指令字串」，這週又修了三種讓字串比對失準的手法。這再次證明：**權限規則是第一層，不是最後一層**，要靠 sandbox 和 hook 補。
- **我該做什麼**：
  - 先 `claude update` 到 2.1.319 以上（安全修正）。
  - 排程或 CI 裡的 `claude -p` 加上 `--settings '{"permissions":{"denyInsteadOfPrompting":true}}'`，再檢查 exit code（見第 2 節「本週必試」）。

## 2. 🛠️ Claude Code 本週更新

**涵蓋版本：2.1.317–2.1.319**（台灣時間 11/03 07:57、11/04 05:55、11/06 08:58 發布，時間取自 npm registry）。2.1.316 是 10/31 發布，上週已報。以下依主題整理，只挑會改變工作方式的。

### 權限、auto mode 與 sandbox（跟本週深度主題直接相關）

- **`permissions.denyInsteadOfPrompting`**（2.1.319）：會跳權限提示的呼叫改成直接拒絕，turn 繼續。→ **我可以怎麼用**：所有無人看管的執行都開；互動式工作不要開，否則 Claude 會默默跳過該問你的事。
- **安全修正**（2.1.319）：環境變數前綴藏指令的 Bash 繞過、`sed` 跳過權限檢查、建立 worktree 時的 sandbox escape、含引號字詞讓 deny／ask 規則漏比對、`/rewind` 透過目錄 symlink 還原或刪除檔案。→ 這些都不需要你改設定，**更新就好**。
- **規則語意變嚴**（2.1.319）：session 裡比較精確的 Bash `ask` 規則，如果被更廣的 `deny` 涵蓋，直接拒絕而不是詢問；`which` 帶非查詢類 flag 要問；專案設定或 plugin 不能再把你在專案外關掉的 auto mode server 檢查打開。→ 「deny 一律優先」的原則更一致了。
- **寄出你的 email 前先問**（2.1.317）：web 或 shell 工具呼叫要把你的帳號 email 送到網路上時會先詢問。
- **Auto mode 在 LLM gateway 後面**（2.1.319）：telemetry／feature flag 關閉時，server 檢查不到的呼叫改成詢問或拒絕，不再退回內建 classifier（`CLAUDE_CODE_AUTO_MODE_SERVER=0` 保留舊行為）。你直接用 claude.ai 登入的話不受影響。
- **Sandbox 下的巢狀 skills**（2.1.319）：開了 Bash sandbox 時，子資料夾裡 `.claude/skills` 的 skill 只有在你從那裡啟動或 `/cd` 過去時才載入。→ 防止 clone 下來的子專案偷塞 skill。

### MCP

- **MCP tasks 進背景**（2.1.319）：長時間的 MCP 工具（例如跑一次完整回測、匯出大量資料）不再卡住對話。→ **我可以怎麼用**：W44 的 stock-screener MCP server，如果把「重建資料快取」做成 task，Claude 可以邊等邊做別的事。
- **呼叫還沒載入的工具時回傳 input schema**（2.1.318）：tool search 延遲載入的工具，第一次叫錯會直接拿到正確參數格式，少一輪來回。
- **`deniedMcpServers` 的 URL 條目也會擋 Anthropic 提供的同 URL server 和 cloud session 的 connector**（2.1.318）。
- 修正：舊版握手的 MCP server 連不上或回空結果（2.1.319）；`claude mcp add/remove` 改成持鎖寫入（2.1.318）。

### Subagents 與背景工作

- **`/tasks` 新增「Earlier in this session」**（2.1.319）：已完成的 subagent 可以重新打開、繼續傳訊息，重啟後也找得到。→ 讓 subagent「補做」或「解釋剛才的判斷」不用重開一個。
- **不同模型的 subagent 用該模型自己的 effort**（2.1.317），不再沿用主對話的 effort。→ W44 談過分層 effort，現在預設行為更合理：Haiku subagent 不會被主對話的 `max` 拖慢。
- **背景 subagent 的 shell 指令 3 分鐘後自動移到背景**（2.1.318），避免 prompt cache 過期（cache 過期就要整段重新計費）。
- **安全機制停掉 subagent 後**，Claude 會改用更窄的 prompt 重試或告訴你，而**不是自己動手做**（2.1.319）。
- `/clear` 不再殺掉背景 agent 和 teammates 正在跑的指令（2.1.319）；`SendMessage` 給執行中的背景 agent 會更早送達（2.1.317）。

### Context 與成本

- **Read 工具移除「檔案沒變」的替身回應**（2.1.317）：重讀沒改過的檔案會回傳**完整內容**。→ 好處是不會再「以為讀了其實沒讀」；代價是重讀大檔會吃 context。請 Claude 讀大檔時指定範圍。
- **`/context` 不再每回合把完整視覺化表格送給 Claude**（2.1.319），只送精簡表格；每個清單只列最大的 10 項。→ 之前常跑 `/context` 的 session 會省下不少 token。
- 修正：自動 compaction 後「Prompt is too long」（CLAUDE.md 很大又改過時）、idle compaction 用非摘要的回覆取代對話、超長對話 compaction 時遺失早期摘要（2.1.317–2.1.318）。
- **Grep／Glob 超時只拿到部分結果時，Claude 會知道是部分結果**（2.1.317）。→ 以前它可能把「沒搜完」當成「不存在」。

### Hooks

- **PostToolUse 在 turn 被新訊息打斷後仍會執行**（2.1.319），最多 10 秒。→ W41 的「跑完測試才算完成」hook，打斷時不會再漏掉。
- **Agent SDK hook callback 支援 `onFailure: "block"`**（2.1.317）：callback 自己壞掉時擋下動作，而不是放行（fail-closed）。

### 腳本與自動化

- **`claude -p` 失敗時 exit 1 的情境變多**（2.1.317、2.1.319）：auto mode 因沒有安全檢查而拒絕、磁碟滿、`--resume` 時找不到 MCP server。→ 腳本要檢查 `$?`。
- **登入到期提醒**（2.1.318）：`claude auth status` 顯示 `loginExpiresAt`、`claude -p` JSON 有 `credential_expires_at`、到期前 10 天 stderr 警告。→ 排程任務可以提早知道要重新登入。
- **自訂節奏的 `/loop` 改成：回合結束沒有重新排程就停止**（2.1.319），要舊行為設 `CLAUDE_CODE_LOOP_KEEPALIVE=1`。
- **`/claude-api latency-optimize`**（2.1.319）：分析你的 Claude API 程式哪裡讓使用者等，用你的 eval 測試更快的設定。

### 用量

- 用 `ant auth login` 的 Console 登入計費時，啟動會顯示被計費的 Console 組織，claude.ai 登入失效時會警告（2.1.319）。→ 避免以為在用訂閱額度，其實在燒 API 費用。

### ⭐ 本週必試：`permissions.denyInsteadOfPrompting`

1. 找一個你會讓 Claude 自己跑的工作（例如 badminton-expense 的 `npm test`）。
2. 執行：
   ```bash
   claude -p "跑 npm test，然後 git push" \
     --settings '{"permissions":{"denyInsteadOfPrompting":true,"allow":["Bash(npm test)"]}}' \
     --output-format json; echo "exit=$?"
   ```
3. 預期：`npm test` 會跑，`git push` 被**拒絕而不是卡住**，Claude 會在結果裡說它沒有權限推送。
4. **審查**：看 JSON 結果裡 Claude 有沒有誠實說「push 沒做」，而不是說「完成」。如果它說完成了，這就是你在排程任務裡最需要防的情況。

## 5. 💡 開發者應用

### 5.1 無人看管的 `claude -p`：讓它「失敗得大聲」

本週三個變更合起來，可以把排程或 CI 裡的 Claude 改成可靠的形式：

```bash
claude -p "$PROMPT" \
  --settings '{"permissions":{"denyInsteadOfPrompting":true}}' \
  --output-format json > result.json
status=$?
jq -r '.credential_expires_at // empty' result.json   # 快到期就提醒自己
[ $status -ne 0 ] && echo "Claude 失敗：$status" && exit $status
```

- `denyInsteadOfPrompting`：沒被允許的動作**拒絕**，不卡住。
- exit code：2.1.317／2.1.319 起，auto mode 拒絕、磁碟滿、找不到 MCP server 都會 exit 1。**以前很多情況是 exit 0 卻沒做事**（W42 談過靜默失敗）。
- `credential_expires_at`：排程任務最常見的死因是登入過期。
- **最後一定要驗證結果**，不要只看 Claude 的自述：例如 `npm test` 再跑一次、`git log -1` 看有沒有 commit。

來源：[CHANGELOG](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md)

### 5.2 Read 不再回「沒變」的替身：重讀大檔要算成本

2.1.317 起重讀沒改過的檔案會回傳完整內容。badminton-expense 的 `src/Logic.js` 有 616 行，一個 session 裡讀 5 次就是 5 份。做法：

- 在 CLAUDE.md 寫「讀大檔請用 offset／limit 只讀需要的範圍」。
- 長任務中段跑 `/context` 看是哪些檔案占最多（2.1.319 起 `/context` 本身也不會再每回合浪費 token）。
- 要「重新看一下現況」時，請 Claude 用 `git diff` 而不是重讀整個檔案。

### 5.3 平行 agent：先問「誰負責合併」

Conductor 被收購正好是檢視平行開發流程的機會。它的核心其實就三件事：**每個 agent 一個 worktree、一份清楚的任務描述、人類 review 後合併**。在 Claude Code 裡：

- `claude --worktree <名稱>` 或 agent view 開背景 session；每個 session 給它**不重疊的檔案範圍**（W44 的 `blockWritesOutsideWorkingDirectories` 可以硬性鎖住）。
- 合併前讓**另一個沒參與的 subagent**做 review（W43 提過「挑毛病不要用 fork」）。
- 你的五個專案都是一人專案、單一主分支，**同時跑 2 個 agent 已經是上限**；超過的話 review 的人（你）會變成瓶頸，品質反而下降。

來源：[InfoWorld](https://www.infoworld.com/article/4245065/meta-acquires-conductor-as-ai-coding-shifts-toward-multi-agent-development.html)

### 5.4 「一年 244 個版本」的疲勞：怎麼跟上而不被拖著走

## 7. 🔬 深度主題：Claude Code 權限設計：allow／ask／deny、設定分層，以及「不要再問」的代價

> 前四週的主題是「驗證（hooks）」「分工（subagents）」「context（CLAUDE.md、skills）」「接外部工具（MCP）」。這週補上最底層的一塊：**Claude Code 被允許做什麼**。這是讓前面幾塊安全運作的基礎。以下除非另外註明，都取自官方 [Configure permissions](https://code.claude.com/docs/en/permissions) 和 [Settings](https://code.claude.com/docs/en/settings) 文件。

### 7.1 背景：從「每次都問」到「規則先決定」

Agent 越能自己做事，權限提示就越多；提示一多，人就會開始**不看內容直接按 Yes**（approval fatigue）。Claude Code 的回應是一整套分層：

1. **權限規則**（allow／ask／deny）：預先決定哪些動作免問、必問、禁止。
2. **權限模式**（Manual、acceptEdits、plan、auto、dontAsk、bypassPermissions）：改變「沒有規則命中時」的預設行為。
3. **Hooks**（PreToolUse）：用你自己的程式碼檢查每個呼叫。
4. **Sandbox**：作業系統層級限制 Bash 的檔案和網路存取。

Apiiro 的研究暴露的是第 1 層的副作用：**你為了減少提示而按的「don't ask again」，本身就是一條被寫進檔案的規則**。

### 7.2 運作原理

**規則格式**：`工具名(規格)`。

| 工具 | 例子 | 比對方式 |
| :- | :- | :- |
| Bash | `Bash(npm test)`、`Bash(git log *)` | 比對整條指令文字，`*` 代表任意文字 |
| Read／Edit | `Read(./.env)`、`Edit(src/**)` | gitignore 語法；裸檔名在任何深度都比對 |
| WebFetch | `WebFetch(domain:api.line.me)` | 比對 hostname，`*` 不跨越點 |
| MCP | `mcp__stock__*` | 整個 server 或單一工具 |

**比對順序**：「Rules are evaluated in order: deny, then ask, then allow. The first match in that order determines the outcome, and rule specificity doesn't change the order.」也就是：

- `deny: Bash(aws *)` 會擋掉 `aws s3 ls`，**就算** allow 有 `Bash(aws s3 ls)`。allow 不能在 deny 裡開例外。
- `ask` 也贏過 allow：你在本機按了「don't ask again」，如果專案設定有對應的 ask 規則，**你還是會被問**。

**萬用字元的位置很重要**：`Bash(git log *)` 只允許 `git log`；`Bash(git *)` 允許所有 git 指令（包括 `git push --force`）。結尾 `*` 前面有空格時也比對裸指令：`Bash(ls *)` 比對 `ls`。

**設定分層**（優先度高到低）：managed → `--settings` 命令列 → `.claude/settings.local.json`（你的、這個專案）→ `.claude/settings.json`（團隊共用，進 git）→ `~/.claude/settings.json`（你的、所有專案）。但**權限清單是合併的，不是覆蓋**：五個來源的 allow、ask、deny 全部加在一起，再依 deny → ask → allow 判斷。所以「任何一層的 deny 都無法被別層的 allow 解除」。

**「don't ask again」存到哪裡、存多久**（官方表格）：

| 工具 | 「Yes, and don't ask again」 |
| :- | :- |
| Bash | **永久**，每個 repo、每條指令 |
| 檔案修改 | 只到 session 結束 |
| WebFetch | **永久**，每個 repo、每個網域 |

永久的規則寫進**repo 根目錄**的 `.claude/settings.local.json`（worktree 會寫到主 checkout）。Claude Code 第一次寫這個檔案時，會把它加進**全域 git excludes**；手動建立的則要自己加 `.gitignore`。另一個細節：**如果這個檔案被 git 追蹤了，Claude Code 會把它當成 repo 提供的檔案，要你信任資料夾後才套用**，這是防止別人在 repo 裡塞 allow 規則。

**Hooks 跟規則的關係**：PreToolUse hook 在權限提示之前執行，**hook 回傳 allow 也不會跳過 deny／ask 規則**；反過來，hook 用 **exit 2** 擋下，就算有 allow 規則也會被擋。注意：「Exit code 1 without valid JSON output is a non-blocking error … If your hook is meant to enforce a policy, use `exit 2`.」（[Hooks 文件](https://code.claude.com/docs/en/hooks)）

### 7.3 Bash 規則為什麼脆弱

官方自己警告：「Bash permission patterns that try to constrain command arguments are fragile.」例如 `Bash(curl http://github.com/ *)` 擋不住：

- 參數順序不同：`curl -X GET http://github.com/...`
- 協定不同：`curl https://github.com/...`
- 轉址：`curl -L http://short.example.com/xyz`
- 變數：`URL=http://github.com && curl $URL`

而且 deny 規則**不比對用完整路徑呼叫的同一個程式**（`/usr/bin/curl`），也不比對 `sh -c "..."` 裡面的內容。本週 2.1.319 又修了三種繞過（環境變數前綴、`sed`、含引號字詞）。結論：

> **用 allow 規則「開放」窄的、精確的指令；用 sandbox 的網路／檔案限制「封鎖」危險能力；用 PreToolUse hook 做字串規則做不到的判斷。** 不要靠 deny 字串去擋「有創意的」指令。

### 7.4 優缺點與適用情境

| 機制 | 適合 | 不適合 | 失效方式 |
| :- | :- | :- | :- |
| allow 規則 | 每天重複的安全指令（`npm test`、`git status`） | 含參數變化的指令 | 寫太寬（`Bash(git *)`）、**把秘密存進去** |
| deny 規則 | 讀取敏感檔（`Read(./.env)`）、整個工具（`WebFetch`） | 擋 Bash 的特定參數 | 換寫法就繞過 |
| ask 規則 | 部署、push、刪除等不可逆動作 | 高頻動作 | 疲勞後亂按 Yes |
| PreToolUse hook | 內容檢查（秘密、路徑、時段） | 需要語意判斷的事 | exit code 寫錯、解析失敗時放行（fail-open） |
| Sandbox | 網路白名單、限制寫入範圍 | MCP 工具、hook 本身的程式 | 例外清單太大 |
| auto mode | 互動式開發、減少提示 | 無人看管又沒有 server 檢查的環境 | classifier 判斷錯誤 |
| `denyInsteadOfPrompting` | headless、排程、subagent | 互動式工作 | Claude 默默跳過該做的事卻說完成 |

### 7.5 在 Claude Code 工作流程中怎麼用

**一個人的專案，建議這樣分配**：

- `~/.claude/settings.json`（全部專案）：
  ```json
  {
    "permissions": {
      "deny": ["Read(**/.env)", "Read(**/.env.*)", "Read(**/.clasp.json)", "Read(~/.clasprc.json)"],
      "ask": ["Bash(git push *)"]
    }
  }
  ```
  `.clasprc.json` 是 clasp 存 Google OAuth token 的地方（待確認你的路徑），`.clasp.json` 只有 scriptId 不算秘密，但沒必要讓 Claude 讀。
- `.claude/settings.json`（專案共用、進 git）：該專案固定的測試、建置指令放 allow，部署放 ask。例如 badminton-expense：`allow: ["Bash(npm test)", "Bash(npm run build)"]`、`ask: ["Bash(npm run deploy)", "Bash(clasp *)"]`。這樣規則**看得到、能 review、不含秘密**。
- `.claude/settings.local.json`：只放個人臨時偏好，**每月打開看一次**。
- PreToolUse hook：擋「指令裡出現 token」（本週實作）。
- 無人看管執行：加 `denyInsteadOfPrompting`，再驗證結果。

**習慣層面**：

1. 按「don't ask again」前看一眼它要存的規則（提示上會寫「don't ask again for: npm test *」）。**裡面有秘密、有 `*` 在危險位置，就只按 Yes**。
2. 用 `/permissions` 定期檢視：它會列出每條規則來自哪個檔案。

## 8. 📖 本週三詞

### Global git excludes（全域 git 排除檔，`core.excludesFile`）
- **定義**：對**這台電腦上所有 repo** 生效的 ignore 清單，不在任何 repo 裡。
- **運作原理**：git 判斷要不要忽略一個檔案時，依序看 repo 的 `.gitignore`、`.git/info/exclude`、全域 excludes。設定在 `git config --global core.excludesFile`，沒設就用 `$XDG_CONFIG_HOME/git/ignore`（通常是 `~/.config/git/ignore`）。
- **例子**：Claude Code 把 `**/.claude/settings.local.json` 寫進這個檔案，所以你在這台電腦 `git add -A` 不會加到它。**但換一台電腦、重灌，或用 `git add -f` 就不保護你**。這就是為什麼 repo 自己的 `.gitignore` 也要寫一份（只有 price-tracker 有寫）。用 `git check-ignore -v <路徑>` 可以看到是哪個檔案的哪一行讓它被忽略。

### MCP Tasks（非同步工具呼叫）
- **定義**：MCP 規格中讓 server 把一個耗時的 tool call 當成「task」執行的機制，client 先拿到 task 代號，之後再查詢狀態或取得結果，不用一直佔著連線等。
- **運作原理**：client 在請求中表示支援 task → server 回傳 task ID 和狀態（working、completed、failed 等）→ client 輪詢或等通知 → 拿結果。Claude Code 2.1.319 的做法是：一看到 task 就把它移到背景，完成時再告訴 Claude。
- **例子**：stock-screener 的「重新抓取並建置 point-in-time 資料」可能要幾分鐘。做成 task 後，Claude 可以先去寫測試，資料好了再回來分析。

### zkSNARK／Provable inference（可證明推論）
- **定義**：zkSNARK 是零知識證明的一種，可以證明「我正確執行了某個計算」，而不透露計算的私密輸入；**provable inference** 把它用在模型推論上，證明某個回應確實是由某組權重算出來的。
- **運作原理**：廠商先公布權重的密碼學承諾（像指紋）→ 推論時同時產生證明 → 任何人拿承諾、prompt、回應就能驗證，不需要權重。FlashProve 的數字：每個證明約 18.78 MB、單執行緒驗證約 21 秒、產生證明的 GPU 成本是一般推論的 70–95 倍。
- **例子**：你透過某個便宜的第三方 API（W44 談的「AI relay」）呼叫「Opus」，現在無法確認背後真的是 Opus；有了可證明推論，就能驗證有沒有被換成便宜模型。目前還是研究原型。

## 10. 🔍 審查題 ×2

### 第 1 題（易）：badminton-expense 的 `planAdd`，被 AI「改成現代寫法」

原本的 `planAdd` 會比對既有紀錄，同一天同一個人只記一筆。AI 說它「用 Set 和 for…of 改寫，邏輯不變、可讀性更好」。找出問題：

```js
/**
 * 比對既有紀錄：同日同人只記一筆。
 * 回傳 { add: [{date, name, fee, isNew}], dup: [{date, name}] }
 */
function planAdd(entries, records) {
  const canon = canonicalNames(records);              // nameKey → 第一次出現的寫法
  const seen = new Set(records.map(r => `${r.date}|${r.name}`));
  const add = [], dup = [];

  for (const e of entries) {
    for (const n of e.names) {
      const k = nameKey(n);                           // trim + toLowerCase
      const isNew = !canon[k];
      const name = canon[k] || n;
      const key = `${e.date}|${name}`;

      if (seen.has(key)) {
        dup.push({ date: e.date, name });
        continue;
      }
      add.push({ date: e.date, name, fee: e.fee, isNew });
    }
  }
  return { add, dup };
}
```

提示：想想使用者傳「11/5 Amy amy」，或是試算表裡同一個人有「Amy」和「amy 」兩種寫法時會怎樣。

### 第 2 題（難）：AI 寫的「擋秘密」PreToolUse hook，註解說「已測試，可以擋住 token」

這是你在本週實作可能拿到的產出。設定檔把它註冊成 `PreToolUse`、matcher 為 `Bash`。找出會讓它**形同虛設**的問題，以及設計上的瑕疵：

```js
#!/usr/bin/env node
// .claude/hooks/block-secrets.js
// PreToolUse(Bash)：指令裡出現疑似憑證就擋下
const TOKEN_PATTERNS = [
  /Bearer\s+[A-Za-z0-9+/=._-]{20,}/,
  /LINE_TOKEN=\S+/,
  /AKfycb[\w-]{40,}/,          // Apps Script 部署 ID
];

let raw = '';
process.stdin.on('data', chunk => (raw += chunk));
process.stdin.on('end', () => {
  let input;
  try {
    input = JSON.parse(raw);
  } catch {
    process.exit(0);           // 解析失敗就不要擋，避免卡住工作
  }
  if (input.tool_name !== 'Bash') process.exit(0);

  const cmd = input.tool_input.command;
  const hit = TOKEN_PATTERNS.find(p => p.test(cmd));
  if (hit) {
    console.error(`偵測到疑似憑證（${hit}），請改用 Script Properties 或環境變數`);
    process.exit(1);           // 非 0 = 失敗 = 擋下
  }
  process.exit(0);
});
```

提示：先查 Claude Code 文件裡 hook 的 exit code 有幾種意思。再想想「誰會在 Bash 指令裡打 `bearer`」。

## 11. ⚠️ 風險與辨識

### Windows 會默默去掉檔名結尾的點：Copilot 在 Visual Studio／SSMS 用 `settings.json.` 繞過受保護檔案檢查（CVE-2026-103572，待確認）

- **發生什麼**：研究者 Embrace The Red 揭露，Copilot 寫入 `settings.json.`（結尾多一個點）時，**Windows 會把它當成 `settings.json`**，於是繞過「不准改設定檔和 MCP server 設定」的檢查，進而執行任意指令。CVSS 8.8、Important，8 月通報，Microsoft 已修補（發布日期待確認，網站連不上）。同時期 Copilot CLI 也有 CVE-2026-29783（bash 參數展開的指令注入，0.0.423 修正）。
- **為什麼跟你有關**：你寫過 C#、可能在 Windows 上用 AI 工具。這類漏洞的共同模式是**「檢查用的字串」和「作業系統實際用的路徑」不一致**：結尾的點和空白、大小寫（2.1.319 也改了 macOS／Windows 大小寫不同的路徑提示）、短檔名（`PROGRA~1`）、symlink（本週 `/rewind` 修正）。
- **怎麼辨識與防範**：
  - Windows 上的 AI 工具保持最新；設定檔和 hooks 目錄可以考慮設成唯讀。
  - 自己寫路徑檢查（例如 PreToolUse hook 檢查 Edit 的目標）時，**先正規化路徑**（`path.resolve`、`fs.realpathSync`、去掉結尾的點與空白），再比對。
- 來源：[Embrace The Red](https://embracethered.com/blog/posts/2026/visual-studio-copilot-remote-code-execution/)（待確認，網站連不上）、[SentinelOne：CVE-2026-29783](https://www.sentinelone.com/vulnerability-database/cve-2026-29783/)

## 審查題解答

<details>
<summary>第 1 題解答（易）：<code>planAdd</code></summary>

**Bug 1：`seen` 用原始的 `r.name` 當 key，比對時卻用正規化後的 `canon[k]`。**

- 原本的程式是 `seen[r.date + '|' + nameKey(r.name)]`，比對用 `nameKey`（去空白、轉小寫）。改寫後，既有紀錄存的是 `"2026-11-05|amy "`，新的 key 是 `"2026-11-05|Amy"`（canon 是第一次出現的寫法）。**兩者不相等，同一個人同一天被記兩次**。
- 只要試算表裡同一個人出現過兩種寫法（有人打「Amy」，有人打「amy」），就會發生。這正是原本 `nameKey` 要防的事。

**Bug 2：加入 `add` 之後沒有更新 `seen`，也沒有更新 `canon`。**

- 原本的程式在加入後執行 `seen[...] = true`，並且在 `isNew` 時設定 `canon[k] = n`。改寫後兩個都拿掉了。
- 後果：「11/5 Amy amy」或兩行都寫同一天同一個人，**同一則訊息裡的重複不會被抓到**，會記兩筆；而且兩個都被標成 `isNew`，摘要會顯示兩個「新成員」，寫法還不一樣（「Amy」、「amy」）。

**修正**：key 一律用 `${date}|${nameKey(name)}`；加入後 `seen.add(key)`；`isNew` 時 `canon[k] = n`。

**怎麼抓到**：AI 說「邏輯不變」的重構，**拿原本的測試跑一次**（`npm test`）。如果測試沒涵蓋「大小寫不同」和「同一則訊息重複」，就請 Claude 先補這兩個測試、在**舊版**上確認通過，再套用重構。

</details>

<details>
<summary>第 2 題解答（難）：<code>block-secrets.js</code></summary>

**Bug 1（致命）：`process.exit(1)` 不會擋下工具呼叫。**

- Claude Code 的 hook：exit 0 是成功，**exit 2 是 blocking error**（PreToolUse 會擋下呼叫，stderr 回傳給 Claude），**其他非 0（包括 1）是 non-blocking error，動作照常執行**。官方文件特別寫：「Exit code 1 without valid JSON output is a non-blocking error … If your hook is meant to enforce a policy, use `exit 2`.」
- 所以這個 hook 偵測到 token 時會印出警告，然後**指令照樣執行**。註解「非 0 = 失敗 = 擋下」是 Unix 慣例，但不是 Claude Code 的語意，這是 AI 最容易犯的「看起來合理」的錯。
- **修正**：改成 `process.exit(2)`，或輸出 `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"..."}}` 再 exit 0。

**Bug 2：解析失敗時放行（fail-open）。**

- 安全用途的 hook，「我看不懂輸入」應該擋下（fail-closed），而不是 `exit 0`。另外 `input.tool_input.command` 如果不存在，`p.test(undefined)` 會把 `undefined` 轉成字串 `"undefined"` 比對，不會出錯但也不會擋，一樣是放行。
- **修正**：catch 裡 `exit 2`；`command` 不是字串也 `exit 2`。

**設計瑕疵**：

- **大小寫敏感**：`/Bearer\s+.../` 沒有 `i` flag，`authorization: bearer xxx`（curl 範例常見小寫）就漏掉了。HTTP header 名稱和 scheme 本來就不分大小寫。
- **誤擋部署 ID**：`AKfycb...` 是 Apps Script 的部署 ID，已經寫在 commit 進 git 的 `package.json` 裡，不是秘密。擋它會讓 `clasp update-deployment` 被擋，你就會想把 hook 關掉；**誤報太多的安全機制最後都會被關掉**。
- **秘密進了錯誤訊息**：目前只印出 regex，沒問題；但如果有人把它改成印出 `cmd`，token 就會出現在 Claude 的 context 和 transcript 裡。擋下時只描述「哪一種」，不要回顯內容。
- （延伸）這個 hook 只看 Bash。秘密也可能透過 `Write` 寫進檔案、透過 `WebFetch` 的網址送出；要完整防護，matcher 要涵蓋這些工具，或把秘密完全留在 Claude 碰不到的地方（Script Properties）。

**怎麼抓到**：不要相信「已測試」。**自己餵一個假 token 給 hook，看 `$?`**（本週實作第三次的第 2 步）。看到 `exit=1` 時，回頭查文件的 exit code 定義。
